# N1 — automatic backups and pre-migration snapshot

Branch `wp/N1-backups`. Approved defaults in `docs/ROADMAP.md` §5. No migration, no new `SettingKey`
(the second folder is remembered in `UserDefaults`, like the data folder).

## Store API (for N2)

`AbacusStore/Backups/BackupStore.swift`:

```swift
let store = try BackupStore.standard()          // ~/Library/Application Support/Abacus/Backups + remembered mirror
try await store.snapshot(of: database, reason: .preWrite)          // -> BackupSnapshot, thrown on failure
try await store.snapshotIfDue(of: database)                        // .automatic when newest > 24 h old, else nil
store.list()                                                       // newest first
```

`SnapshotReason`: `.automatic .manual .preMigration .preWrite .preRestore`. Files are
`abacus-<UTC yyyyMMddTHHmmssZ>-<reason>.abacus`, complete SQLite copies restorable by `SQLiteBackup.restore`.
Retention (every snapshot, both folders): newest of each of the last 14 days and 6 months, plus the last 3
`.preMigration`. A tests/tool caller must pass its own `BackupStore(folder:)` in a temp folder.

`AbacusDatabase.open(at:backups:now:)` — pass a store to take the `.preMigration` snapshot when an existing
database has migrations pending (best effort: a failed snapshot does not block the migration). The default
`backups: nil` never writes anywhere, so tests and tools are unaffected.
