# S3 — Budget Save states, Rules tester removed, stability check (D54, D56)
State: done (waiting for merge)   ·   Branch: wp/S3-polish   ·   Updated: 2026-10-27

## Done
- **Budget Save button (D56)** — `BudgetEditorModel.saveState: BudgetSaveState`
  (`.unchanged` / `.edited` / `.saved`):
  - page opened or reverted, nothing edited → `.unchanged`: blue, disabled, "Save";
  - any edit (limit text, limit currency, add/remove limit, total, total currency, applies-from
    month) → `.edited`: blue, enabled, "Save"; Revert enabled;
  - successful save → `.saved`: green, disabled, "Saved" with a checkmark, until the next edit
    (even one typed back to the saved value; setting a field to its current value is not an
    edit);
  - failed save → stays `.edited` with the error shown.
  - A reload right after saving (section shown again, data changed elsewhere) keeps "Saved" while
    the loaded values equal the saved ones (amounts compared as stored: "4100" = "4100.00").
  - Bug found in the app snapshot: the model's `baseline` was `@ObservationIgnored`, so after a
    save the view (which had only read `isDirty`) was never invalidated and stayed on
    "Unsaved changes" / blue Save. `baseline` is observed now.
  - `save()` now requires `canSave` (valid and edited): no save without an edit.
  - View: `BudgetSaveButtonStyle` in `BudgetView.swift` (a disabled bordered-prominent button
    loses its colour on macOS, so the colours are drawn by the style; blue dimmed while disabled).
  - DEBUG: `-AbacusBudgetDemo edited|saved` edits (and saves) the first limit for UI snapshots.
- **Rules page**: the "Try a description" row (description, amount, account picker), the result
  line and the match highlight are gone; page search and category filter stay; the rule editor
  sheet is unchanged. Tester model code removed from `RulesModel` (`probe`, `probeAccountID`,
  `probeAmountText`, `probeAmountMinor`, `match`, `probeResult`, `RuleRow.isMatch`, the `probe:`
  init parameter); nothing else used it. "New rule" now opens an empty draft (it used to take
  the tester's text). Tests that matched through the tester now call `RuleMatcher` (what imports
  use) on the page's rules.
- **Stability check (D54)** of both screens:
  - Budget: no `Binding($optional)`, no index-based bindings (limit text and currency bindings
    go through the category id with `firstIndex` guards), no force unwraps in the view. Removed
    the one force unwrap in the model (`loadedPlan!.id` in `save()`). No Escape handler on the
    page; Escape there has nothing to dismiss.
  - Rules: the editor sheet reads through `draftBinding` (falls back while the draft is nil,
    writes only when there is one) and `draft` falls back to an empty `RuleDraft`; the sheet's
    `isPresented` binding and the Cancel button (`.cancelAction`, Escape) both call
    `cancelEditor()`, which is idempotent. Alerts capture their pending confirmation (C9). No
    force unwraps or index bindings in the page or sheet.
