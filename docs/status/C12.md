# C12 Accounts — status

_Branch `wp/C12-accounts`. TA v1.6 R-MGMT-1, R-MGMT-8, R-MGMT-9, R-MGMT-10, R-MGMT-11, R-HOME-1,

## Done

- **Account groups (D48).** New entity `AccountGroup` (`accountGroups`: id, name, position,
  optional colorHex) and `Account.groupID` (nil = top level). The Swift property `groupName` is
  gone; the column stays in the table, unused (append-only). `AccountRepository` gained
  `groups()`, `saveGroup(_:)`, `deleteGroup(_:)` (accounts move to the top level) with protocol
  defaults (`[]` / throw) so read-only fakes keep compiling; SQLite and `ManagePreviewStore`
  implement them, the dashboard / transactions preview stores return `PreviewData.accountGroups`.
- **Migration "v11: account groups"** (registered last, after "v9: category createdAt"; "v10" is
  left to the debts lane C14 — the orchestrator orders them at merge). Creates `accountGroups`
  and `accounts.groupID TEXT REFERENCES accountGroups(id) ON DELETE SET NULL` + index (each only
  if missing). Every distinct trimmed non-empty `groupName` becomes a group (ids lowercase UUID
  text, as SQLiteData binds). Custom order keeps what the page showed: groups in the order of
  their first account (position, name, id), each followed by its accounts, then the ungrouped
  accounts; numbered 0, 1, 2… across that sequence. Nothing else changes (balances, transactions,
  net worth). CloudKit-safe: single PK, no UNIQUE, only SET NULL; backup copies tables dynamically.
- **Ordering model.** A group and the top-level accounts share one `position` space; accounts in
  a group sort by their own `position` among siblings. `AccountOrder.tree(_:groups:by:)` builds
  the one-level tree for `AccountSort` (Name A–Z, Name Z–A, Custom order).
- **Accounts page** (`App/macOS/Manage/Accounts/AccountsView.swift`, `AccountsModel`): full-width
  `PageSearchField`; under it the currency filter menu (All currencies / EUR / USD / PLN / UAH,
  `Currency.displayOrder`), the sort selector (remembered in `SettingKey.accountSort`, default
  Custom order) and a "New group" icon button; "Show archived accounts". Groups are folder rows
  with "N accounts" and the sum of their non-archived accounts in the display currency at the
  latest rate (like net worth; "—" when a non-zero balance has no rate); accounts in a group are
  indented. Search matches account and group names (a matching account brings its group, dimmed
  if the group itself doesn't match; a matching group shows its accounts). With a search or the
  currency filter, empty groups hide. Group sums ignore the filters (always the whole group).
- **Drag and drop like Reminders / Categories** (`AccountsModel.drop(_:on:position:)`,
  `canDrop`): top/bottom ~28 % of a row = between rows (reorder; the sort switches to Custom
  order and what the user saw becomes the custom order), middle = onto (an account moves into
  that group, last; onto an account inside a group = into that group; sort unchanged). One level:
  a group never goes into a group; next to an account in a group = into that group there; right
  below a group whose accounts follow = its first account; between top-level rows = top level
  (out of its group); the space below the list = top level, last. Hidden (archived / filtered)
  rows keep their place: the plan runs over the full tree. Balances never change.
- **Inspector.** Account form: Group is now a picker ("None (top level)" + groups A–Z); moving an
  account to another group puts it last there. "New account" starts in the selected group (or the
  selected account's group). Group form: name, optional colour, "N accounts" + sum, "Delete
  group…" (confirmation; accounts move to the top level). Save / Create bottom-right, Revert /
  Cancel left of it, ⌘S (`AccountSaveFooter`, R-MGMT-10). Toolbar: "New account" only.
- **Pickers everywhere (R-MGMT-8).** Shared helper `AbacusFeatures/Manage/AccountOrder.swift`:
  `pickerSections(_:groups:)` — groups A–Z, each with its accounts A–Z, **ungrouped accounts
  after the groups**, in a section without a header (a database without groups shows one plain
  A–Z list); `alphabetical` (flattened), `label` ("PKO › PKO Personal"), `byName`
  (`localizedStandardCompare`). App view `AccountPickerItems` renders sections with group
  headers. Used by: transaction editor (Account / From / To; `TransactionEditorModel.accountSections`),
  transactions account filter (group headings, indented accounts), import "Import into" picker
  (`ImportWizardModel.targetSections`), import account-mapping and transfer-account pickers
  (A–Z, labels "Group › Name · CUR"), rules tester account and Account-is / transfer account
  pickers (`RulesModel.accountSections`). Events have no account picker. The editor's fallback
  default account (no remembered one) stays the first active account in custom order.
- **Net worth widget (R-HOME-1).** `DashboardNetWorth.breakdown`: groups with the sum of their
  counted accounts (display currency; "—" when one lacks a rate), the accounts indented beneath,
  then ungrouped accounts, in the Accounts page's custom order; groups without a counted account
  are left out. `accounts` (flat) unchanged. Only `DashboardNetWorthCard.swift` and the net worth
  part of the model changed (`LoadedData.accountGroups`, one load line, one `make` argument).
  DEBUG launch option `-AbacusNetWorthExpanded YES` opens the breakdown for snapshots.
- Debt-kind accounts are untouched (they group and sort like any account).
- PreviewData: groups Monobank / PKO / Revolut (ids 151–153); account positions renumbered the
  way v11 numbers them (relative order unchanged); seeded by `PreviewData.seed` and sample data.
