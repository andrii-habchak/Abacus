# C1 — Transaction-list filters
State: done   ·   Branch: wp/C1-filters   ·   Updated: 2026-10-22

Scope: the Phase 3 filters on the contracts from `27d03cb` — `TxnQuery.includeUncategorised`
and `TxnQuery.importBatchIDs` — in the store, the in-memory fakes, the Transactions screen, the
dashboard's Uncategorised slice and the import wizard's "Show transactions".

## Done
- Store (`SQLiteTxnRepository`): `includeUncategorised` matches expenses and incomes whose own
  category is empty (transfers never), OR-combined with `categoryIDs` (attached-record
  categories still match as before); `importBatchIDs` keeps only rows with that
  `Txn.importBatchID`. `list(matching:)` totals: with Uncategorised the main amount without a
  category counts; attached records without a category do not (`TxnTotals` gained
  `includeUncategorised:`, default false). `SQLiteReportQueries` takes no `TxnQuery`, so
  nothing to change there.
- Fakes: `TransactionQueryMatcher` honours both fields identically; the dashboard preview store
  now delegates to it (the manage and transactions preview stores already did).
- `TransactionFilters`: `includeUncategorised`, `importBatch: ImportBatch?` (kept whole for the
  chip), `importBatch(_:)` (every date, `allDates`), `isCategoryFiltered`;
  `drillDown(category: nil, month:)` = Uncategorized slice → expenses only + Uncategorised.
  Both map to `TxnQuery`; `clear()` resets them.
- Totals: `TransactionTotalsRule` / `TransactionListContent` take `includeUncategorised`.
- Transactions screen: "Uncategorised" checkbox at the top of the Categories popover, shown
  when `hasUncategorised` (checked on `load()` with a `TxnQuery(includeUncategorised: true)`) or
  when ticked; chip label "Uncategorised" / "N categories". "Import: <file> · <date>" chip
  (date `Oct 21, 2026`) with an × that removes only the import filter; "Clear filters" also
  clears it. The all-dates range shows "All dates" in the date chip (also for undated events).
- Dashboard: `DashboardModel.select` returns `categoryID: nil` for Uncategorized (nil only for
  Refunds); `DashboardDrillDown.query(categoryID: nil, …)`; `Slice.drillsDown` enables the
  legend row. `DashboardView.onDrillDown` takes an optional category; RootView's handler is
  unchanged (`TransactionFilters.drillDown` accepts the optional).
- Import: `AppSession.showTransactions(ofImport:)` (batch from the wizard's history or last
  summary); RootView's `.importFiles` route calls it. "Show transactions" added to every
  not-undone history entry next to "Undo import…".
- Tests: `TxnRepositoryTests` (3 new) and `UncategorisedImportFilterTests` (9) named
  R-HOME-3, R-LIST-2, R-LIST-5, R-IMP-6. `swift test` green; app `BUILD SUCCEEDED`.

## Notes / interpretations
- The dashboard's Uncategorized slice (Reporting) also counts expense attached records without
  a category; the drill-down follows the `TxnQuery` contract (main transaction without a
  category), so such fee lines are not listed. Rare in practice (the editor and imports give
  lines a category).
- The Uncategorised drill-down also sets the type filter to Expense, since the donut shows
  expenses only; ticking Uncategorised by hand keeps every type.
- `hasUncategorised` fetches the uncategorised rows on every `load()` (section switch); fine on
  the real data (~280 rows). A count query on the protocol would make it cheaper if needed.
