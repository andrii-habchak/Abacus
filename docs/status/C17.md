# C17 — Debts linked to bank transactions
State: in progress   ·   Branch: wp/C17-debt-linking   ·   Updated: 2026-10-30

TA v1.8 `R-DEBT-9…13` (D58). Builds on C14 (`docs/status/C14.md`): a record that moves money
owns one leg (`Txn.debtRecordID`); unflagged leg = one-sided transfer (`isRefund` = money in),
flagged leg = expense/income in "Debts". This file starts with the design (written before
coding), then progress.

## Design

### One operation: link a transaction to a debt (R-DEBT-9)

Every path (import row action, rule, convert in the list) ends in one store operation,
`DebtLinking.convert(txnID, link, db)` (AbacusStore), inside the caller's database transaction:

- input `DebtLink` (AbacusDomain): person name, debt id (nil = the person's debt in `currency`,
  found by person key — an unsettled one first — else created), `currency`, kind (nil = suggested
  from the direction and the debt's balance at that moment), amount in the debt's currency
  (nil = the leg's amount; required when the currencies differ), "count in reports" flag;
- only an expense or income that is not yet a leg can be linked (transfers between my accounts
  never); the kind must move money in the transaction's direction (out: I lent, I repaid, Paid on
  their behalf; in: They repaid, I borrowed);
- the record: debt, kind, day of the transaction, amount, note = the transaction's note,
  `importBatchID` = the transaction's (so undoing that import removes the record too);
- the transaction becomes the leg **in place**: same id, date, payee, note, event, attached
  records, fingerprints, import batch, original amount; type/category as C14's `leg()` wants them
  (unflagged → one-sided transfer, `isRefund` = money in; flagged → expense/income in "Debts").
- a new debt gets the transaction's `importBatchID` (undo removes it when no records are left);
  a settled debt that gets a record is reopened (otherwise money owed would hide in Settled).

Kind suggestion (`DebtRecordKind.suggested(inflow:balance:)`): out → I repaid when the balance
is negative (I owe them), else I lent; in → They repaid when the balance is positive, else I
borrowed.

### Matching hand-entered records (R-DEBT-13)

- `Flow.of` reads a one-sided inflow leg (`isOneSidedInflow`) as money **in** (bug found by the
  orchestrator: every transfer was "out").
- `RowAnalyzer`: an existing **leg** on any existing account the row touches, same amount, same
  direction, ±3 days, any description, from another source than the row (a leg created from this
  bank's own import has its fingerprint, and two real repayments of the same amount must not
  swallow each other) → a new claim kind `debtLeg` (after settle/same-transfer/completes, before
  fuzzy duplicates; one leg per row, one row per leg, closest day first). Also checked for rows
  that would go to Needs review (a Saldo half or an unknown PKO type for a payment to a person).
- Preview: status **Already imported**, detail "Matches the debt record “Lent to Ann” of …",
  plan `link` → the row's fingerprints are stored on the leg, so a re-import is an exact match.
  No second transaction; balances do not change.

### Import action (R-DEBT-10)

- `ImportDebtChoice` (person, debt id or new, currency, kind, report flag). New rows
  (expense/income, also a possible duplicate imported anyway): `ImportPreview.setDebt(_:forRow:)`
  (nil = back to normal; a rule's debt can be removed with `.notDebt`). Review rows: new
  `ReviewChoice.debt(ImportDebtChoice)`.
- The row's plan creates the transaction as usual (expense/income without category, money
  direction kept) and the commit carries `ImportCommit.debtLinks` (txn id + `DebtLink`); the store
  converts them after inserting the transactions, oldest first, in the same database transaction.
- Default debt: the person's debt in the row account's currency, else "New debt in <currency>".
  Another currency can be picked; the amount is then converted at the day's rate (pipeline
  `converter`, the app's rate table), or taken from the row's original amount when it is in that
  currency; without either the row gets an issue that blocks the commit.
- The suggested kind uses the debt's balance plus the effect of this import's earlier debt rows.
- Row label "Debt record · Lent to Ann", detail names the debt; the summary counts "N debt records".

### Rule action (R-DEBT-12)

- `RuleAction.debt` (raw `debt`) + `CategoryRule.debtPersonName`; migration **v12: rule debt
  person** adds the nullable column (CloudKit-safe, append-only).
- Matching: the first rule that matches and can act wins, as before; a debt rule acts on any
  expense/income with a non-blank person. On import it applies where a transfer rule would (no file
  category, no user pick): the row becomes a debt record for that person, debt = the person's debt
  in the account's currency (else new), kind from the direction and the running balance (rows in
  date order). Rule hits are counted.
- "Update existing transactions": `RuleEffect` gives the leg shape; `SQLiteRuleRepository.apply`
  converts each transaction with `DebtLinking` (kind suggested, oldest first) and records the
  application. Roll back turns legs that still hold the rule's state back into what they were
  and deletes their records (debts the rule created stay, empty).
- Rule editor: action "Record as debt for" + person name field (existing people offered).

### Convert in the Transactions list (R-DEBT-11)

Context menu "Convert to debt record…" on an expense/income that is not a leg: a sheet with person
(existing or new name), debt (the person's debts + "New debt in <account currency>"), kind
(suggested), "Count as expense/income" where C14 offers it, and — when the debt's currency differs
from the account's — the amount in the debt's currency pre-filled at the day's rate. Save calls
`DebtRepository.convert`. Shared draft logic: `AbacusFeatures/Transactions/DebtLinkDraft.swift`;
shared sheet: `App/macOS/Transactions/DebtLinkSheet.swift` (used by Import too).

### Undo of an import batch

- Records created by the batch (import action or rule) carry the batch id: undo deletes them, then
  the transactions (legs), then debts the batch created that have no records left.
- A transaction of the batch converted later in the list: its record also carries the batch id
  (taken from the transaction), so undo removes record and leg together — the debt balance never
  keeps a record whose money is gone.
- A hand-entered record matched by the batch (R-DEBT-13): only the fingerprints the batch stored
  are removed; the record and its leg stay.
