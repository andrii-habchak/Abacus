# C5 Colours — status

_Branch `wp/C5-colours`. TA R-MGMT-7, R-EVT-1, R-CAT-1, R-ACC-1; decision D45._

## Done

- **Palette** `AbacusDomain/Model/ColorPalette.swift`: 14 distinct mid-tone colours (readable in
  light and dark mode, carry a white letter), names for accessibility, `needsColor` (nil,
  invalid, or grey = channels within 30), `pick(avoiding:)` = random among the least-used.
- **Event colour**: `Event.colorHex` (init parameter after `budgetCurrency`, default nil).
- **Migration `"v4: colours"`** (registered after v3 in `Schema.swift`): adds `events.colorHex`
  (nullable TEXT, only if missing), then `ColorFill.fillAll(replacingGrey: true)`: every category,
  account and event with no colour or a grey one gets a palette colour; set colours stay (e.g. a
  red "Uncategorised", slate `#5C7B99` counts as a colour). Categories avoid their siblings'
  colours (same kind and parent) and a subcategory its parent's; accounts and events avoid each
  other. Plain SQL on the needed columns only, so later entity changes cannot break it. Restore
  migrates the backup copy first, so old backups get colours too; backup/restore copy columns
  dynamically (no list to update).
- **Store creation paths** (`AbacusStore/Repositories/ColorFill.swift`): category, account and
  event `save` fill a missing colour; import commit fills created accounts/categories/events;
  default categories (subcategories now get their own distinct colour, Fees no longer grey) and
  sample data seeding fill too.
- **Manage editors**: `ManageColorField` (`App/macOS/Manage/Categories/ManageColorField.swift`):
  palette swatches + system colour panel ("Custom colour"); used in the Categories, Accounts and
  Events inspectors. New drafts start with a random palette colour apart from their siblings.
  Account tiles use the account colour (blue/red by kind only when none); event rows show a dot.
- **Transaction icons**: the tile uses the category colour, falling back to the parent's
  (`TransactionCategoryTree.color`); transfers and no-category rows stay neutral grey. Dashboard
  donut and event category bars already used category colours (unchanged).
- **Live refresh**: Accounts/Categories/Events models call `onDataChange` after save, archive,
  delete and reorder; `AppSession` then re-reads the transaction list's reference data
  (`TransactionsViewModel.referenceChanged()`) and the dashboard if loaded. `reference` changes
  rebuild the rows at once.
- Preview data: accounts and events have colours; Fees and income categories no longer grey or
  identical.

Note on the owner report ("Uncategorised" red, its transactions grey): the import creates one
"Uncategorised" per kind (expense and income), so the other one may still have been uncoloured;
the list itself already re-read categories on section switch. Both are covered now (fill +
explicit refresh).
