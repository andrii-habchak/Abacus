# C19 — Debt core
State: done (awaiting merge)   ·   Branch: wp/C19-debt-core   ·   Updated: 2026-10-30

TA v1.9 `R-DEBT-16…20` (D59–D61). Builds on C14/C17. Lanes C20 (UI/widget), C21 (Transactions
filter), C22 (import/rules/convert) build on this once merged. This file: design, what is done,
interpretations and questions for the owner, what the next lanes must finish, and the exact public API.

## Design

### Data model (migration v13, append-only, CloudKit-safe)

- `debts`: no currency any more. One row per person (`Debt.personKey`). `countsInNetWorth` defaults to
  **false** for new debts (Swift init, R-DEBT-21, D61); existing rows keep their value (merged rows: on if
  any merged debt was on).
- **`debtAccounts`** (new): `accountID` is the primary key (so an account is in at most one debt by
  construction, no UNIQUE needed), `debtID` (CASCADE), `role` (`external` | `virtual`), `createdAt`.
  Entity `DebtAccountLink`. Deleting an account or a debt removes the link only.
- **Virtual account** = an `Account` of kind `.debt` in the chosen currency, linked as `virtual`; no
  statement. **External** = any of the person's real accounts (any kind), linked as `external`.
- **Opening balance per account** = the account's own `openingBalanceMinor` / `openingDate` (no second
  column): a linked account's balance (opening + transactions) is its contribution.
- `debtRecords` = **manual records** only (forgive, adjustments): new column `currency` (filled from the
  old debt). Kinds and stored sign unchanged (positive = they owe me). `Txn.debtRecordID` stays as a
  column (append-only) but nothing writes it any more.
- Sign: a linked account's balance is the debt balance as stored: money into the person's account = they
  owe me more (positive). Display sign (R-DEBT-21, D61) is C20's.

### Balance and net worth

- Per debt, per currency: `Σ over linked accounts (opening + signed effects of every transaction touching
  it, attached lines included) + Σ manual records of that currency`. Never netted across currencies; the
  converted total in the display currency is a separate calculator.
- `DebtBook` is self-contained for calculators: debts, links, linked accounts, the transactions touching
  them (`TxnWithLines`), manual records.
- Net worth: linked accounts leave the account part (breakdown and totals) always; a debt adds one term
  per currency only when its flag is on (asset while positive, liability while negative). So an account is
  counted once: through the debt or not at all, never twice. An archived linked account still carries its
  debt.

### Transfer to a debt (replaces the record-leg path)

`transferToDebt(txnID, to: DebtLink)` takes an expense/income on my own account and turns it, **in place**
(same id, date, description, event, original amount, fingerprints, import batch), into a transfer between
the own account and the person's account:

- money out (expense / income reversal) → `account` = mine, `toAccount` = theirs (they owe me more);
- money in (income / expense refund) → `account` = theirs, `toAccount` = mine (they repaid, or I borrowed);
  attached records of an inflow become their own transactions on my account (they would hit the person's
  account otherwise);
- cross-currency: the person's side takes `link.amountMinor`, else the transaction's original amount when it
  is in that currency, else `amountUnknown`;
- the debt is `debtID`, else found by person key (unsettled first), else created; the account is
  `accountID` (must be linked to that debt, else `notDebtAccount`), else the debt's **virtual** account in
  `link.currency` (default: my account's currency), created when missing. New debts and accounts carry the
  transaction's import batch, so undoing that import removes them when they are empty. A settled debt that
  gets money is reopened. Refused (`notLinkable`): transfers, and transactions on an account that itself
  belongs to a debt.
- `unlinkTransfer(txnID)` is the reverse (expense/income on my account, no category).

### Migration v13 (what it does, in order)

1. `debtRecords.currency` (from the debt), table `debtAccounts`;
2. debts merged per person key (oldest survives; flag = any; due = earliest; settled only if all; notes
   joined), records re-pointed;
3. every debt's `sourceAccountID` account is linked to its (merged) debt as `virtual`;
4. each record with a leg: the leg becomes, in place, a transfer to the debt's virtual account of the
   record's currency (the linked source account of that currency is reused and unarchived, else a new
   `Person (CCY)` account is created); the record is deleted. Records without a leg stay manual records.
   Amounts are exact on both sides (`toAmountMinor` set whenever currency or amount differs);
5. `debts.currency` dropped (`ALTER TABLE … DROP COLUMN`).

`DebtMigrationV13.run(db) -> Result` returns the counts the tests and the real-data report use. The
v10 conversion is frozen as `DebtConversionV10` (inside migration v10 only); the runtime
`DebtConversion.convertDebtAccounts` (after every import commit) now only **links** unlinked debt-kind
accounts to a debt found by name or created, rewriting nothing.

### Hints
- duplicate (R-DEBT-20): two different linked accounts of one debt, a transaction on each, same currency,
  same amount and direction, ≤ 3 days apart (never the same transaction), paired once, closest day first;
- idle (R-DEBT-21): a linked account of an open debt with no transaction in the last `periodDays`
  (default 30).

## Interpretations (owner to confirm)

1. **`debts.currency` is dropped** (`DROP COLUMN`), the only dropped column so far: a NOT NULL column without
   default cannot stay once the struct has no currency. CloudKit sync is not enabled, so no deployed schema
   depends on it. Tell me if the "append-only" rule must hold even here (then the struct would keep a
   hidden legacy currency field).
2. **Merging debts per person:** "Count in net worth" of a merged debt is on if any merged debt was on.
   A conflict changes net worth by the converted balance of the debts that were off (reported as
   `flagConflicts`; the real export has none). Due date = earliest, notes joined with a line break.
3. **Flagged legs** ("Count as expense/income" on I lent / Paid on their behalf / They repaid) become plain
   transfers: the report flag is lost for them (`droppedReportFlags`, 0 in the real export). The flag stays
   on manual records (forgive), which still report through `DebtBook.reportLedger()`.
4. **A leg of an inflow moves to the person's account** (`accountID` = theirs, `toAccountID` = mine): a
   transfer always starts at its source. Its attached records (fees) become separate transactions on my
   account so my balance does not move.
5. **Source accounts are reused as virtual accounts** (unarchived) instead of creating new ones, so the
   Accounts list does not get duplicates of what v10 archived.
6. **Deleting a debt keeps its accounts and their transactions** (they become ordinary accounts again;
   C14 deleted the legs, which changed my balances). Unlinking an account never touches transactions.
7. **Runtime link of debt-kind accounts** (after every import): found by name (case/diacritic-insensitive),
   else a new debt that counts in net worth like the account did (non-archived), settled when archived;
   this differs from "new debts do not count" because it keeps net worth unchanged.
8. **A transfer to a debt keeps the bank's description** (no "Lent to Ann" rewrite), as in C17.
9. **Idle hint period** default 30 days, duplicate window 3 days (TA says "short window").
10. A debt created by an import (or a later convert of its rows) is removed by undo only when it has no
    manual record and no linked account that the import did not create.
11. The person's balance across **linked accounts of any kind** is counted from the account balance, so an
    external account's own transactions that are not payments (fees, her other spending) count too: that is
    what "importing a statement updates the debt" means; say if some should be excluded.

## Questions

- R-DEBT-19 says matching is "same amount, direction, ±3 days": should a bank row that matches a hand

- Should the virtual account of a person's debt be created automatically for the first payment (done) or

## Public API (for C20/C21/C22)

AbacusDomain (`Model/Debts.swift`)
- `Debt` (`personName`, `dueDay`, `note`, `countsInNetWorth` default false, `isSettled`, `sourceAccountID`,
  `importBatchID`, `createdAt`, `personKey`, `Debt.personKey(_:)`) — no `currency`.
- `DebtAccountRole { external, virtual }`; `DebtAccountLink(accountID, debtID, role, createdAt)` (id = account).
- `DebtRecord(debtID, kind, day, amountMinor, currency, note, reportKind, categoryID, fingerprint,
  importBatchID, createdAt)`, `balanceEffect`; `DebtRecordKind` unchanged (+ `linkable(inflow:)`,
  `suggested(inflow:balance:)`).
- `DebtBook(debts, links, accounts, txns, records)`: `records(of:)`, `links(of:)`, `accounts(of:)`,
  `debtID(ofAccount:)`, `linkedAccountIDs`, `debt(_ id:)`, `debt(person:)`, `personNames`,
  `personNames(matching:)`, `balances(of:calendar:) -> [Money]`, `balance(of:currency:calendar:) -> Int64`,
  `reportLedger(calendar:)`. (`DebtRecordEntry`, `entries`, `leg`, `debt(person:currency:)`, `debts(person:)`
  are gone.)

AbacusDomain (`Calc/DebtCalc.swift`, `Calc/NetWorth.swift`)
- `Calc.debtBalances(_:through:calendar:) -> [Debt.ID: [Money]]` (per currency, display order EUR, USD, PLN,
  UAH; zero entries listed for currencies the debt touches), `Calc.debtBalance(_:debtID:currency:through:calendar:)`,
  `Calc.debtAccountBalances(_:debtID:through:calendar:) -> [DebtAccountBalance(accountID, role, balance)]`,
  `Calc.debtConvertedTotal(_:debtID:currency:converter:rateDate:through:calendar:) -> DebtConvertedTotal(total?, unconverted)`,
  `Calc.debtSummary(_:currency:converter:calendar:)` (`DebtPersonSummary` gained `debtID`),
  `Calc.debtAccountFlows(_:debtIDs:) -> [DebtAccountFlow(accountID, role, outMinor, inMinor, transactions)]`,
  `Calc.debtDuplicateHints(_:windowDays:calendar:) -> [DebtDuplicateHint]`,
  `Calc.debtIdleAccountHints(_:today:periodDays:calendar:) -> [DebtIdleAccountHint]`.
- `Calc.netWorth` / `netWorthSeries(…, debts:)`: linked accounts only through the debt; `DebtValue` is one
  line per (debt, currency), `id` is a String.

AbacusDomain (`Protocols/DebtRepository.swift`)
- `DebtRepository`: `book()`, `save(Debt)` (throws `personExists`), `delete(Debt.ID)`, `save(DebtRecord)`,
  `deleteRecord`, `link(_:to:role:)` (throws `accountLinkedElsewhere`), `unlink(_:)`,
  `createVirtualAccount(for:currency:name:openingBalanceMinor:)` (+ convenience without name/opening),
  `transferToDebt(_:to: DebtLink) -> DebtTransferResult`, `unlinkTransfer(_:)`, `personNames(matching:)`.
- `DebtLink(personName, debtID?, accountID?, currency?, amountMinor?)`, `DebtTransferResult(txnID, debtID,
  accountID, createdDebt, createdAccount)`, `ImportDebtLink`, `DebtRepositoryError { personExists,
  accountLinkedElsewhere, invalidRecord, notLinkable, amountUnknown, notDebtAccount, notDebtTransfer }`.

AbacusStore
- `SQLiteDebtRepository(database:calendar:)` implements it; also `static book(_ db)`,
  `static save(_ record:, _ db)`, `static createVirtualAccount(for:currency:name:openingBalanceMinor:importBatchID:, _ db)`.
- `DebtLinking.transfer(_:to:_ db)`, `DebtLinking.unlinkTransfer(_:_ db)`.
- `DebtConversion.convertDebtAccounts(_ db, calendar:, now:) -> Result(accounts, debtsCreated)`.
- `DebtMigrationV13.run(_ db) -> Result`; `DebtConversionV10` (frozen, migration v10 only).
