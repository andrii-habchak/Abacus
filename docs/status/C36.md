# C36 — Import: Needs review tab, selection, rule on unknown types
State: done (awaiting merge)   ·   Branch: wp/C36-import-review   ·   Updated: 2026-10-31

Owner feedback from testing 1.5.0 (import wizard).

## 1. Selection on the Needs review cards (bug)
- **Root cause.** The model was fine (selection state is shared, card ids are the row ids, `select(_:mode:)`
  and the bulk actions handle review rows, covered by tests). The view was not: in `ImportReviewCard` the
  tap handler sat only on the title line (title + date). A click on the description, the empty space or
  the card border did nothing, and a Cmd or Shift click there fell through, so building a multi-selection
  by clicking the cards failed. Rows on the Transactions tab have the handler on the whole row.
- **Fix.** The handler now sits on the card's background shape (behind the radios, pickers and buttons,
  with a card-shaped `contentShape`), so the whole card selects while the controls keep their own clicks.
  The selected card is filled with the accent tint (not only a border). `importSelect` reads the modifiers
  of the click being handled (`NSApp.currentEvent`) together with `NSEvent.modifierFlags`.
- Tests (`ImportReviewTabTests`): Cmd toggle and Shift range over review cards (and across into the category
  rows), Select all inside a sub-filter, selection cleared on a sub-filter or tab change; bulk Category on
  review cards (records the row as its kind with the category; mixed income/expense selection; mixed with
  category rows), bulk Skip + Undo, bulk Account (transfer), bulk Debt.

## 2. Bulk bar Category
Expense / Income category menus replaced by the shared searchable `CategoryPicker` (C34). Items come from
`ImportWizardModel.bulkCategoryPickerItems(kind)` = `CategoryPickerItem.items(from:kinds:)` over the active
categories in picker order. A pick applies at once to the selected rows of that kind; a mixed selection shows
two pickers ("Expense category", "Income category"). The old "+ New category…" menu entry is now a small
"+ New…" link button next to the picker (the picker has no trailing action). The Account menu is untouched.

## 3. Tab structure
- "Category assignment" tab removed (`Tab.categoryAssignment` gone). The Needs review tab has a segmented
  control: **All (N+M)** (default), **Decisions (N)** (the review cards), **Categories (M)** (rows that still need
  a category, same row list style as the old tab, with its header).
- In All the cards come first, then a "Rows that need a category" section; Shift ranges over that order.
- Tab label and the top Needs review card show N+M; the card caption is unchanged.
- A row is counted once: a row waiting for a decision is listed only as a card (its row item has no category
  cell), so the two lists are disjoint and the total is N+M.
- Selection, bulk bar and Select all work inside the visible sub-filter; changing it (or the tab) clears the
  selection. `ImportWizardModel.reviewFilter` / `ReviewFilter`, `categoryRows`, `visibleReviewItems`,
  `visibleCategoryRows`, `needsReviewTotal`, `reviewFilters`.
- The row's "Open" button on the Transactions tab opens Needs review on Decisions.
- Footer text "N transactions still without a category" is unchanged: it counts transactions that will import
  without a category (including a review row recorded without one), not the list.

## 4. Rule on "Unknown operation type" rows
`ImportPreview` resolver (`ruleResolvesUnknownType`): a PKO row of unknown operation type (kind by sign) is
resolved as income (money in) or expense (money out) with the rule's category, source "By rule …", and does
not enter Needs review, when an enabled category rule matches it (text, amount, account scope, as for any
row) and its category kind agrees with the sign. A rule of the other kind, a disabled rule, or an
account-scoped rule of another account does not resolve it. A row the user already decided in review keeps
its decision. Transfer candidates for other reasons (`transferAmountUnknown`, unpaired halves) are not
touched. On the Transactions list such a row shows "Unknown operation type, recorded by its sign" instead of
the parser's "Needs review" warning. Tests: `UnknownTypeRuleTests` (6).

## Interpretations
- N counts all review rows (also decided ones), as the old tab label did; M counts rows still needing a category.
- A review row that is recorded without a category stays a card (counted in N), not in M.
- The "+ New…" button is a link-style button beside the picker.

## Proposed requirement text (TA R-IMP, replaces R-IMP-10)
R-IMP-10: The Needs review tab lists the rows that need a decision and the rows that still need a category,
each row once, with the filters All, Decisions and Categories; the tab and the Needs review card show the total.
Click, Cmd+click and Shift+click select rows and cards alike; the bulk bar acts on the selection of the visible
filter.
R-IMP-5 addition: an unknown PKO operation type that an enabled category rule of the matching kind (income for
money in, expense for money out) matches is recorded by that rule and does not wait for review.

## Not checked visually
