# R2 — Faithful README screenshots
State: done   ·   Branch: wp/R2-screenshots   ·   Updated: 2026-10-28

The R1 screenshots were painted with `cacheDisplay`, which does not draw `NSGlassEffectView`
(sidebar, toolbar glass, segmented thumbs) or the window's title-bar buttons, so the sidebar was
an approximated grey box and the traffic lights were missing. The dashboard showed only the top.

## Capture approach
- `App/macOS/Shell/WindowSnapshot.swift` (DEBUG) now captures each visible app window with
  **ScreenCaptureKit**: `SCShareableContent.currentProcess` (only this process's windows) →
  the `SCWindow` whose `windowID` is the `NSWindow.windowNumber` →
  `SCContentFilter(desktopIndependentWindow:)` → `SCScreenshotManager.captureImage` at the
  filter's `pointPixelScale`, no cursor, no shadow (`ignoreShadowsSingleWindow`); the window's
  rounded corners stay transparent. This is the window server's own composite: real sidebar
  material, toolbar glass, selected segments and coloured traffic lights.
- **It worked without Screen Recording permission**: no prompt, no denial, on this Mac
  (launched from the terminal). The old `cacheDisplay` paint is kept as a
  fallback and logs `painting … with cacheDisplay` if ScreenCaptureKit ever fails.
- Before capturing, the snapshot activates the app and makes the Settings window key when it is
  open (else the main window), so the chrome looks active.
- New DEBUG launch options:
  - `-AbacusDisplayCurrency EUR` — sets the display currency (persisted in the scratch database,
    and the rates page's "Show in" follows it as it would on a launch with that default).
  - `-AbacusSnapshotFullPage YES` — grows the main window until its page scroll view shows its
    whole document (the clip view's toolbar inset is subtracted), then captures it. AppKit keeps
    windows inside the screen (`constrainFrameRect(_:to:)`), so for this run only the main window
    is moved to a runtime subclass that returns the frame unchanged; the window reaches below the
    screen and ScreenCaptureKit still captures all of it.
- `RootView` passes the session to `WindowSnapshot.runIfRequested(session:)` (one-line change).

## Screenshots (`docs/screenshots/`)
All taken from the Debug build, each launch with a fresh `CFFIXED_USER_HOME=<scratch>/home.XXXX`,
`-AbacusDatabasePath <that home>/demo.sqlite -AbacusLoadSampleData YES -AbacusDisplayCurrency EUR
-AbacusWindowWidth 1280 -AbacusWindowHeight 860 -AbacusSnapshotDelay 3` plus `-AbacusSection …`.
Captured at 2x (2560 px), scaled to 1600 px wide with `sips --resampleWidth 1600`
(`settings-general.png` stays at its native 1120 px). `pngquant` is not installed; the largest
file is the full dashboard at about 470 KB.
- `dashboard.png` — full page, 1600 × 1979: all six widgets in the default order (Net worth;
  Monthly budget + Monthly expenses; Income vs expenses; Monthly income + Debts) and the rates
  footnote. `-AbacusSnapshotFullPage YES`.
- `dashboard-dark.png` — top part, `-AbacusDark YES`.
- `transactions`, `accounts`, `categories`, `budget`, `debts`, `rules`, `import` (step 1,
  section `importFiles`), `rates` — 1600 × 1075.
- `settings-general.png` — the Settings window (`-AbacusOpenSettings general`), key window.

Each PNG was opened and checked by eye: sidebar flush with the window edges and with its real
material, traffic lights coloured, toolbar and the EUR segment selected (Settings › General shows
EUR), only sample names (Alex Example, Sam Placeholder, …), nothing clipped (the full dashboard
ends below the Debts card with its footnote). Rate dates in the toolbar vary between pages
(sample rates vs a live fetch finishing during the run); that is the app's real behaviour.

README: the hero image is the full dashboard (alt text lists the six widgets); the screenshot note
says EUR and made-up sample data. STATUS "How to check the UI safely" has one line on the method.
