# C24 — Debt filter fixes
State: done (awaiting merge)   ·   Branch: wp/C24-debt-filter-fixes   ·   Updated: 2026-10-30

Fixes to the C21 debt filter (`R-DEBT-22`) after owner testing of 1.4.0. Owned: Transactions filter
files (`TransactionFilters`, `TransactionsViewModel`, `TransactionFilterBar`, `TransactionsView`) and
`DebtFilterTests`.

## 2. Freeze on removing the debt filter (D54) — cause

Not a didSet/onChange cycle: the model-level apply/remove is instant (tests, large data too).
Reproduced in the real app (DEBUG, scratch database, 5,000-transaction large sample set,
`-AbacusHangWatch YES`): "Show transactions" of a debt uses every date, so removing the debt filter
leaves *all dates, all accounts* = the whole history. The list (a SwiftUI `List` = `NSTableView`)
received those ~5,000 rows as a **diff of inserted rows**, and AppKit sizes every inserted row on the
main thread (`_doAutomaticRowHeightsForInsertedAndVisibleRows`, seen with `sample`): the main thread
stayed blocked (no `HANG` line for the 40 s watched; "reentrant operation in its NSTableView
delegate" warning). The owner's history is bigger than that set. Applying the filter (a dozen rows)
was fast, which is why only removal hung.

Fix (root): the list is keyed by the query of the rows on screen (`TransactionsViewModel.loadedQuery`,
set together with `rows` in `apply`; `List.id(model.loadedQuery)`). A changed query rebuilds the
table in one go (AppKit estimates heights lazily) instead of diffing thousands of inserted rows. Same
5,000-row removal now blocks the main thread for ~0.8 s in a debug build (was a hang). The keyed
identity also covers "Clear filters", the date chip and any other big change of the result set.
Scroll position resets on a filter change (not on edits: same query keeps its identity).

Not done: the date range is not restored when the debt filter is removed (it stays "All dates", as
before; 5,000 rows now cost ~0.8 s). Say if it should return to the previous range.

DEBUG helper to re-check: `-AbacusLoadLargeSampleData YES -AbacusTransactionsDebt ANY
-AbacusTransactionsDebtRemove YES -AbacusHangWatch YES` (scratch database only).

## 1. Chips

- Accounts added by a debt have no chip; the **debt chip** stands for them and reads
  "<name> · N accounts" (N = the debt's accounts still ticked). The "Debt: <name>" popup label is
  unchanged. Un-ticking an account in the menu keeps the debt.
- Accounts the user ticked on their own while a debt filter is active (`independentAccountIDs`, e.g.
  re-ticking an account the debt had added) get their own chip, labelled "Name · CUR"
  (`accountChipLabel`). Without a debt filter there are no account chips (the Accounts popup label
  shows the selection, as before).
- `debtAccountChips` is replaced by `independentAccountChips`.

## 3. Accounts menu follows the debt

- While a debt is selected the Accounts menu lists only the accounts linked to the selected debts
  (union for several; `filters.debtLinkedAccountIDs`, kept in the new `debtLinkedIDs`). Removing the
  last debt restores the full list.
- Rule for independent selections: applying a debt drops selected accounts not linked to any selected
  debt (a debt plus an unrelated account always gave 0 rows); linked ones stay as independent
  entries. Ticking an unrelated account while a debt is selected is ignored. Removing one of several
  debts also drops independent accounts that only belonged to it. Removing the last debt keeps the
  remaining account selection (as in C21).
- Unchanged from C21: debt expands to its accounts, empty case matches nothing,
  `AppSession.showTransactions(ofDebt:)`.
