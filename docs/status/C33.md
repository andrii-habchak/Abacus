# C33 — Categories page actions and the import chip
State: done (awaiting merge)   ·   Branch: wp/C33-categories-actions   ·   Updated: 2026-10-30

Owner-approved requirements: (1) the Transactions import filter becomes one closable chip,
(2) Categories context menu "Show all transactions", (3) Categories context menu "Re-assign…".

## 1. Import filter chip

- `TransactionFilterBar`: the import filter is now a chip (icon, "Import: <file> · <date>" or the file
  name alone in a narrow window, and an ×). The × calls `clearImportFilter()`; no popover, no selection.
  State is unchanged (`TransactionFilters.importBatch`, `.importBatch(_:)` jump from the import
  success step). The chip uses the existing `TxnChipLook` (the blue active look).

## 2. Show all transactions

- Context menu of a category row (also the built-in Uncategorised): "Show all transactions".
  `CategoriesModel.showTransactions(of:)` -> `onShowTransactions` -> `AppSession.showTransactions(ofCategory:)`
  -> `TransactionFilters.category(_:kind:dateRangeBefore:)`: the category selected (a parent covers its
  subcategories through `TxnQuery.categoryIDs`), every date.
- Range restore, analogous to the debt one and independent of it: `dateRangeBeforeCategory` is set to
  the range the list had (or the one it already remembered); clearing the last category entry (the
  `categoryIDs` / `includeUncategorised` `didSet`) puts it back, unless the range was changed by hand
  meanwhile (the `dateRange` `didSet` forgets it). Nothing is remembered when the list already showed
  all dates. "Clear filters" goes to the default as before. The debt behaviour is untouched.
- The built-in "Uncategorised" row uses `includeUncategorised` with the tab's kind
  (`DashboardDrillDown.types`, like the dashboard slice).

## 3. Re-assign…

- Menu item (not for the built-in Uncategorised) opens a sheet: target picker (plain Picker until C34),
  summary "N transactions will move to <target>" (+ attached lines), notes, toggles "Re-point rules that
  use this category" (default on) and "Archive … afterwards" (default off), Cancel / Re-assign.
- Interpretation:
  - Same kind only. Targets: active categories of the kind, A-Z, not the category itself and not its own
    subcategories (the store rejects them with `invalidReassignTarget`, a wrong kind with `kindMismatch`).
  - A parent moves its own transactions and those of all its subcategories. The subcategories stay as
    (now empty) categories unless "Archive afterwards" is ticked, which archives the parent together with
    its subcategories (the store's archive rule).
  - A child moves only its own rows.
  - "Transactions" = `Txn.categoryID` rows plus attached records (fee / cashback / split lines).
    Transfers and balance corrections have no category and are not touched.
  - Rules: `CategoryRule.categoryID`, and the Saldo category import mappings (they decide a
    category the same way a rule does), follow when the option is on; when off both stay.
  - Budget allocations of the category are never moved or merged; the sheet only warns that they stay
    (count of limits in any plan).
  - Nothing to move (no transaction or line): the sheet says so and Re-assign stays disabled.
- Repository (`CategoryRepository`): `reassignImpact(of:)` (counts) and
  `reassign(from:to:repointRules:archiveAfterwards:)` (one `database.write`: txns, attached records,
  rules, mappings, archive; returns what moved). Previews/fakes got default no-op implementations; the
  Manage preview store has a real in-memory one for the model tests.
- Tests: `AbacusStoreTests/CategoryReassignTests` (impact, leaf, parent + lines, rules off, archive,
  transfers untouched, kind / self / own child / missing target rejected, rollback via a failing trigger),
  `AbacusFeaturesTests/CategoryActionsTests` (filters, range restore, debt restore unchanged, session jump,
  menu callback, sheet targets, confirm, nothing to move, import filter clear).

## Proposed requirement text (for the orchestrator)

- R-CAT-5: the Categories context menu offers "Show all transactions" (Transactions filtered to the
  category and its subcategories, all dates; clearing the filter restores the previous range) and
  "Re-assign…" (move all transactions and lines of the category, with its subcategories for a parent, to
  another category of the same kind, optionally re-pointing rules and archiving the category; budget limits
  are not moved).
- R-IMP-6: the import filter in the Transactions bar is a single closable chip.
