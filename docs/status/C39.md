# C39 — Re-assign: searchable picker and the built-in Uncategorised target
State: done (awaiting merge)   ·   Branch: wp/C39-reassign-picker

Owner feedback: the "Move to" Picker was a long flat menu; there was no way to move an imported
category named "Uncategorised" to the built-in one (D47).

## Done

- "Move to" is the shared searchable `CategoryPicker`. Rows (`CategoryReassignSheet.pickerItems`):
  the built-in "Uncategorised (no category)" first, then active categories of the source's kind in
  A-Z order, without the source and its own subcategories. A matching parent shows its children
  (`CategorySearch`).
- The built-in target is `CategoriesModel.uncategorisedID` in the sheet (`targetIsUncategorised`);
  `confirmReassign` maps it to `nil` for the repository. `uncategorisedID` is now `nonisolated`.
- `CategoryRepository.reassign(from:to:...)`: `to` is optional. nil = built-in: `Txn.categoryID` and
  `AttachedRecord.categoryID` (both nullable, so lines lose their category too) become NULL for the
  source and its subcategories (rows of the source's kind by construction). Rules and Saldo
  mappings are left alone whatever `repointRules` says (returned counts 0). Archive afterwards and
  budget limits behave as before. Missing source still `notFound`; kind / self checks apply to real targets only.
- Sheet: summary "N transactions will move to Uncategorised"; re-point toggle disabled with the hint
  "Rules keep pointing at the old category"; a note says attached lines lose their category too.
  The built-in row's own Re-assign stays unavailable.
- Tests: `CategoryReassignTests` (nil target: txns, lines, rules and mappings untouched, budget,
  kind, archive, missing source); `CategoryActionsTests` (picker items, built-in first, exclusions,
  parent-brings-children search, confirm to Uncategorised with archive).

## Not verified visually

Picker button width in the sheet, popover behaviour inside a sheet, the disabled toggle with hint.
The built-in row has no colour dot (the shared picker has no dot support).
