protocols, with in-memory fakes over `PreviewData`. Covers R-MGMT-1…4, R-MGMT-6, R-ACC-1…5,

## Done
- **View models** `AbacusFeatures/Manage/` (`@Observable`, main actor, each with `load()`):
  - `AccountsModel`: groups in order of their first account, ungrouped under "Other" (last);
    balances through today (`Calc.balances`); "Show archived accounts"; inspector draft
    (name, kind, currency locked once the account has transactions, opening balance + date, group,
    IBAN) with Save/Revert; Archive… → dialog ("Its balance is X, not zero… Archive anyway", or a
    plain "Archive" for zero); Unarchive; Delete… only without transactions, hint "Has N
    transactions — archive it instead."
  - `CategoriesModel`: Expense / Income tabs, one-level tree with usage counts, inspector (name,
    parent, colour swatches, usage incl. "and the monthly budget"), New category / New subcategory,
    Archive / Unarchive, drag reorder `move(fromOffsets:toOffset:)` (a parent moves with its
    children; a child dropped under another group joins it), Delete… → reassign dialog with
    same-kind targets (default: a sibling, as the prototype), "Move and delete" / "Archive
    instead"; a parent's children move to the top level (message says so).
  - `BudgetEditorModel`: loads the plan in effect this month; total + currency; "Applies from"
    (this month + 11); limits with "incl. <children>" and share; add/remove; unallocated with
    "Limits exceed the total by X"; Save writes a plan effective from the chosen month (same-month
    plan replaced, others kept — D29) and notes a later plan when there is one.
  - `EventsModel`: rows with dates ("01.10 – 19.10.2026" / "No dates (ongoing)"), spent and
    budget; inspector (name, optional start/end, optional budget + currency), spent by top-level

    Unarchive, Delete… (transactions keep, tag cleared); "Show archived events".
  - `RulesModel` + `RuleMatcher`: tester (first enabled rule whose pattern the description
    contains, ignoring case; per-account rules only on their account, "any account" in the tester
    lets them match), rows (account, "Parent › Child", origin, hits), enable toggles, drag reorder,

  - `ManageDependencies` (`.live(database:refresher:)`, `.preview(store:)`), `ManagePreviewStore`

    `ManageSample` (rules, €300 budget on the Lyon trip, "Car" event and 4 tagged transactions on

## Wiring notes (orchestrator / B1)

  alive in the shell (`@State`) so selection survives switching sections; pass the display currency
  to `AccountsView` (new-account default) and `EventsView`.

- `EventsView(onShowTransactions:)` → Transactions filtered by the event (B3: `.event(_:)` filters).
- Call `load()` on the models after imports/undo or edits elsewhere; `EventsModel.refreshRates()`
  on each `RateRefresher` update.

## Choices to confirm with the owner
- Inspector edits are saved with an explicit **Save changes / Revert** (shown only while there are
  edits); the prototype shows no save control.
- Budget "Applies from" defaults to the **current month** (the prototype showed November selected).
- An event with a budget is shown in the **budget's currency** (spent vs budget compare
  directly); without a budget, in the display currency (R-EVT-3).
- Events: "Show archived events" toggle and a Name field in the inspector (needed for create and
  unarchive; not drawn in the prototype). Rules: an account picker next to the tester, drag to
  reorder, Edit… / Delete… under the table (the prototype only listed rules).

## Blockers / contract-change requests (for the orchestrator)
- None blocking.
- A6: `RuleMatcher` (Manage) is the tester's matcher — first enabled rule in repository order,
  case-insensitive "contains", per-account rules only on their account. The import pipeline's rule
  application (`AbacusImport/Rules`) should use the same semantics (or the tester switches to A6's
  function once merged) so the tester never disagrees with imports.
- Optional: `AccountRepository.balances(asOf:)` and per-category usage counts on the protocols
  would let these screens skip loading every transaction (see Deferred).
- Optional: categorisation rules in `PreviewData` (B5 adds its own in `ManageSample`).

## Deferred
- Performance on 20k transactions (R-NF-2): Accounts, Categories and Events load every transaction
  once per `load()` and compute balances / usage / event totals in memory. If slow, use A5's
  `SQLiteAccountRepository.balances(asOf:)` and count queries.
- R-CAT-3 "reassign children" when deleting a parent: the store moves them up (the only option it
  offers); the dialog says so.
- R-CAT-4 (seeded default categories on first launch) is outside this screen.
- No UI tests of drag-to-reorder; covered by model tests of `move(fromOffsets:toOffset:)`.
