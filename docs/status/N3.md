Balance-correction rows (R-ACC-4, C29) get a "Correction" badge (`Badge.Kind.correction`, own

## 2. Headless `abacus-import` linking — done
The tool's pipeline had no refund / counterpart repositories, so nothing was ever offered. Now it
is wired like the wizard (`SQLiteRefundRepository`, `SQLiteTransferCounterpartRepository`) and,
as nobody can click "Accept", calls `ImportPreview.acceptingOffers()` before `acceptingDefaults()`:
it accepts every refund offer (same description + amount, C35) and every estimated-transfer offer
(C38), in file order, and prints `offers accepted: refunds N · estimated transfers completed M`
(counts only). Unchanged on purpose: a "Transfer to my account" review row whose amount on the other
account is unknown is still recorded by sign (`acceptingDefaults`) — picking a counterpart is a
user decision, not a default. Tests: `HeadlessOffersTests` (C35, C38). The tool's own wiring
is an executable and is covered only by the build plus these preview-level tests.

## 3. Undo of the batch that created an absorbed transaction — done
Problem: batch A imports transaction X; later batch B absorbs X as one side of a transfer (C38) or
completes an estimated transfer A created. X keeps `importBatchID = A`, B holds the snapshot. Undo of
A deleted X, i.e. the transfer, and left B's snapshot orphaned.
Options weighed: (a) refuse undo of A until B is undone; (b) keep the transfer but re-own it to B.
(b) makes undo of A silently leave data of A behind and complicates B's later undo (its snapshot would
restore a row of an undone batch). **Chosen (a)**: `SQLiteImportStore.undo` throws
`ImportUndoError.heldByLaterImport(count:)` when another batch holds a snapshot of one of the batch's
transactions; nothing is changed and the wizard shows "A later import used N transaction(s) of this
one as the other side of a transfer. Undo that later import first." Snapshots vanish when B is
undone (its transactions are restored), after which A can be undone. No data is lost and no
migration is needed. Test: `TransferCounterpartTests.undoEarlierBatchOfAbsorbed` (C38, R-IMP-6).
