# C2 — Settings, data and defaults
State: in progress   ·   Branch: wp/C2-settings   ·   Updated: 2026-10-22

Phase 3 small items deferred by B1/B4/B5: last backup export in the database (R-SET-2), data
folder "Change…" (R-SET-1), default categories on first launch (R-CAT-4), editor rates for old
days (R-EDIT-4, R-FX-1).

## Done
- **Last backup export** (R-SET-2): `DataSettingsModel.lastExport` is a `Day` read from and
  written to `SettingKey.lastBackupExport` (`YYYY-MM-DD`) through `SettingsRepository`.
  B1's interim `LastExportStore` is gone; `LegacyLastExport` reads the old `UserDefaults` key
  `lastBackupExport` once at launch, writes its day into the database and removes the key (a
  value already in the database wins; the key is removed then too). Only the app's own
  database migrates it — previews, tests and `-AbacusDatabasePath` demo databases do not.
- **Data folder "Change…"** (R-SET-1):
  - `AbacusStore/DatabaseLocation.swift`: `DatabaseLocation` remembers the database file in
    `UserDefaults` key `AbacusDatabaseFile` (no value = default location) and `resolve()`s it at
    launch, falling back to the default when the remembered file is missing (the setting is kept,
    so a reconnected drive is used again). `AbacusDatabase.copy(_:toFolder:)` makes a passive
    WAL checkpoint, copies with SQLite's online backup (one consistent snapshot, WAL included),
    opens and migrates the copy, runs `PRAGMA integrity_check` and compares the row count of
    every table; any failure removes the partial copy. It refuses an in-memory database, the
    same folder, a missing folder, an unwritable folder and a folder that already has
    `abacus.sqlite` (never overwritten).
  - `AbacusFeatures/Settings/LiveDataLocation.swift` (replaces B1's `CurrentDataLocation`):
    copy → open → switch the app to a new session on the copy → remember the location → close
    the old database and delete its file (`-wal`/`-shm` too). A failure before the switch
    leaves the old database in use, the old file and the setting unchanged, and shows
    "Couldn't move the database: … Nothing was changed."
  - `AppSessionHost` (new) holds the current `AppSession`; `AppSession.switchDatabase` builds a
    session on the moved file with the same configuration, keeps the selected section, starts
    it, stops the old one and announces "The database is now in “Folder”." in the new Settings
    model. The app reads the session from the host: the main window is rebuilt (`.id`) for the
    new session, Settings keeps its tab, menu commands use the current session. "Show in
    Finder" uses the current session's database URL, so it follows the move.
  - `AppBootstrap.prepare(databasePath:previewData:)` opens the remembered location (or the
    default). With `-AbacusDatabasePath` or `-AbacusPreviewData` the app's own database is no
    longer opened at all (before, bootstrap always opened it), and a demo database's move is not
    remembered.
- **Default categories** (R-CAT-4): `AbacusFeatures/App/DefaultCategories.swift` — on
  `AppSession.start()` a database with no category at all (archived ones count) gets an
  editable set of 22: Food › Groceries / Eating out, Housing › Rent / Utilities, Transport ›
  Fuel / Taxi / Public transport, Health, Bills › Mobile / Internet, Shopping, Travel, Fees,
  Gifts; income Salary, Cashback, Refunds, Other income. English names, one colour per group
  (children share it), no import batch. A database that already has categories (the owner's)
  is never touched.
- **Load Sample Data with the defaults** (`App/SampleDataSeed.swift`): still only into a
  database without accounts; a sample category matching an existing one by name
  (case/diacritic-insensitive), kind and (mapped) parent is reused, an active one before an
  archived one; sample transactions, lines and budget limits are remapped to it. Only
  "Clothing" is added on top of the defaults. A sample id already taken by another category
  gets a fresh id.
- Tests: `LastBackupExportTests` (5), `DatabaseLocationTests` (4, store), `DataFolderMoveTests`
  (4, live sessions on temporary files, separate `UserDefaults` suites),
  `DefaultCategoriesTests` (4). B1's `editorSaveReloads` now looks the Groceries category up by
  name (sample ids are remapped onto the defaults).
