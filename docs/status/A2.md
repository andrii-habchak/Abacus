## Endpoint notes
- Frankfurter v2 returns a flat JSON array `[{"date","base","quote","rate"}]`; errors are
  `{"status":422,"message":"…"}` with HTTP 422. Exact NBU values only for `base=X&quotes=UAH`
  (other bases are derived and rounded), so one request per non-UAH currency.
  `date=<weekend>` returns the previous business day tagged with its own date; ranges skip
  weekends; the latest day is today.
- NBU returns `[{"r030","txt","rate","cc","exchangedate":"dd.MM.yyyy","special"}]` (UAH per 1
  unit, ~45–61 currencies), also for weekend dates (tagged with the requested date), already
  for tomorrow, `[]` for later days, and a non-JSON "Wrong date format" body with HTTP 200.
  The refresher never stores days after today.

## Integration notes (for A5 / B1 / wiring)
- `RateStore.save(_ rates:)` must upsert by primary key: the refresher re-uses the id of a cached
  row with the same `(day, base, quote, provider)` (the UNIQUE index), so a refresh updates rows.
- `RateStore.rates(from:to:)` is called once with 1900-01-01…9999-12-31 to load the whole cache.
- App wiring: one `RateRefresher(store:autoRefresh:)` (auto flag from `SettingKey.ratesAutoRefresh`);
  call `start()` on launch, run `runDailySchedule()` in a task, `ensureRates(for:)` with the days a
  screen converts, `refreshNow()` for "Refresh rates" / "Try again"; observe `updates()`.
- UI badge: `RateSource.badge` is "NBU" for both providers, "Manual" for overrides.
