## Decisions

- **No SDK dependency.** The official Swift MCP SDK would add a package dependency (plus its own
  transitive ones) for a surface Abacus barely uses. The server needs `initialize`, `ping`,
  `tools/list`, `tools/call` over newline-delimited stdio: about 150 lines
  (`Protocol/MCPServer.swift`). Protocol versions 2025-06-18, 2025-03-26, 2024-11-05. Revisit if
  resources, prompts or progress are ever wanted.
- **Read-only connection.** `MCPDatabase.openReadOnly` opens SQLite `readonly`; the server never
  calls `AbacusDatabase.open`, so it cannot migrate. A schema older than this build is an error
  at start ("open Abacus once"); a newer one is read with a warning on stderr.
- **Query layer** (`Queries/`): `AbacusQueries` reuses `Calc.*`, `SQLiteReportQueries` and the
  repositories, so figures match the app. Tool shells (`Tools/ReadTools.swift`) parse arguments,
  call one method and encode the DTO. A CLI can call `AbacusQueries` directly.
- **Privacy:** DTOs carry no `iban`; a test asserts the IBAN never appears in any read output;
  `update_account` cannot set it. Descriptions (payee, note) are returned. Search is capped at 200
  rows and reports the total matched.
- **Propose-then-confirm** is enforced in the server, not left to the client: a write tool's first
  call only returns a summary and a `confirm_token` (8 hex, 10 min, single use, bound to the
  exact arguments); the second call with the token executes. The plan is rebuilt and revalidated
  at confirm time.

## Phase B — write tools (done, behind `--enable-writes`)

`create_transaction`, `update_transaction`, `delete_transaction` (all types, attached records,
refund link `refund_of`, event, original amount); `create_category`, `update_category` (rename,
move, archive), `delete_category` (`reassign_to` when in use); `create_account`, `update_account`,
`archive_account` (no delete, no IBAN, no currency change); `undo_import`, `move_import`.

Safeguards (`Writes/WriteSession.swift`): same repositories as the app (its rules hold: refund
caps, one-level categories, currency lock, kind match); confirm token; at most 200 records per
call (`--max-rows`); one snapshot per session before the first confirmed write, a failed snapshot
stops the write; every executed or failed write appended to `<db folder>/MCP/write-log.jsonl`;
Darwin notification `io.github.andrii-habchak.Abacus.database-changed` after each commit; writes
refused when the file's migrations differ from this build's (newer or older). No restore, no
settings, no account delete tools exist (a test checks the tool list).

## Requests to the orchestrator (shared files)

1. **`Package.swift`: add `"AbacusFX"` to the `AbacusMCP` target's dependencies.** The live rate
   table (`RateTable`) is in AbacusFX. Until then `LiveRates.source` is `NoRates`: only
   same-currency amounts convert, everything else is listed under `unconverted` (the tools say so
   instead of guessing). With the dependency, replace the body of `Queries/LiveRates.swift`
   (the lane can do it in a follow-up commit, or the orchestrator in the same change):

   ```swift
   import AbacusFX
   public enum LiveRates {
     public static let source: RateSource = { database in
       let store = SQLiteRateStore(database: database)
       let rates = try await store.rates(from: Day(year: 1900, month: 1, day: 1), to: Day(year: 9999, month: 12, day: 31))
       return RateTable(rates: rates, overrides: try await store.overrides(), today: Day(Date()))
     }
   }
   ```
   (the same load `RateRefresher.loadCache` does.)
2. **N1's snapshot API → `Writes/LiveSnapshots.swift`.** `SnapshotProvider` is the seam:
   `func snapshot(of: any DatabaseWriter, reason: String) async throws -> String` (returns a short
   description for the log). Once N1 is merged, `LiveSnapshots.provider` becomes an adapter over
   it. Until then `abacus-mcp --enable-writes` exits with "Write tools need the backup snapshot
   API". If N1's API is shaped differently (for example it needs a URL, not a connection), the
   adapter is a few lines; tell the lane.
3. Nothing else outside owned paths. No migration, no `project.yml` change.

## App-side spec for cross-process refresh (later app-UI step; not implemented here)

The app and `abacus-mcp`/`abacus-import` share one SQLite file in WAL mode. The MCP side is done
(short transactions through the repositories, 5 s busy timeout, Darwin notification after each
commit). What the **app** needs, in a place that owns app-session state (`AppSession`, not a
contended screen file):

1. **Poll `PRAGMA data_version` about once a second** on a dedicated reader (value from a
   connection other than the app's writer; `MCPDatabase.dataVersion(_:)` shows the call). It
   changes when *another* connection commits, never for the app's own writes, so a change means
   "someone else wrote". Then reload the visible screens (the same reload a rate refresh does).
   This also covers `abacus-import`. Stop polling when the app is in the background.
2. **Register for the Darwin notification** `io.github.andrii-habchak.Abacus.database-changed`
   (`CFNotificationCenterGetDarwinNotifyCenter` + `CFNotificationCenterAddObserver`, or
   `notify_register_dispatch`) for an instant reload; the poll is the safety net, so a missed
   notification costs at most a second.
3. **Reload when the app becomes active.**
4. **A sheet open on a record that changed meanwhile warns before saving over it.** Keep the
   record's `updatedAt`-like fingerprint (the stored row's values) when the sheet opens; on Save,
   re-read the row; if it differs from the fingerprint, ask "This transaction was changed by
   another program. Replace it with your version?" (Cancel reloads the sheet). A deleted row on
   Save gets the same warning. No schema change needed.
