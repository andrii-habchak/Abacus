# A3 — Saldo parser
State: done   ·   Branch: wp/A3-saldo   ·   Updated: 2026-10-21

## Done
- `AbacusImport/Saldo/`: `SaldoParser: ImportParser` (`canParse` sniffs the header; `parse` →
  `ParsedImport`), `SaldoCSV.swift` (RFC 4180 reader: quotes, `""`, line breaks in quotes, BOM,
  LF/CRLF), `SaldoLeg.swift` (header by column name, three date shapes, amounts, ISO minor units,
  pro rata), `SaldoTransferPairing.swift`.
- Leg patterns (R-IMP-SALDO-1): expense; split over several expense legs; refund (R-TX-4);
  income and income split; income reversal (`kind .income`, `isRefund`); transfer, cross-currency
  transfer, transfer + fee legs as attached expense records (R-TX-6); opening balance from EQUITY
  (R-IMP-SALDO-3); MONEY_ON_THE_WAY halves (+ fee on the outgoing side). Anything else is skipped
  with a file `ImportWarning` naming the Transaction ID and leg types; `skippedRowCount` counts
  skipped Saldo transactions (not CSV lines).
- Amounts: the account leg is the truth. Category legs in another currency become `original`
  (R-CUR-4); splits: legs in the account currency keep their amount, the rest is shared pro rata
  among foreign legs (exact, largest remainder). Transfer fees: in the source currency as is; in
  the target currency pro rata of what was sent; same-currency transfer → fee = sent − received.
- Accounts (R-ACC-2/4): identity (`Account`, `Currency`); BANK_ACCOUNTS → `.bank`, CASH → `.cash`,
  OTHER_ASSETS → `.investment`, LIABILITIES → `.debt`; archived when any leg says `Archived=1`.
  Category legs → `ExternalCategory` (`Parent account`, if ever filled, → `parentName`).
- Pairing (R-IMP-SALDO-2): allowed pairs = equal transit amount + currency, different accounts,
  ≤ 3 days. Among them the matcher takes the **most pairs, then the smallest total time distance**,
  ties → earliest (min-cost matching per independent group). See "Spec gaps" for why not plain
  closest-first. Paired → one `.transfer` with both fingerprints, outgoing half's date/payee;
  unpaired → `.transferHalf` with direction, transit amount and the MOTW name as hint.
- Tags → `tag` (first non-empty across legs, warning if several differ); notes → `note`.
- Row warnings for unbalanced legs, estimated splits, transfers to self, refund records.
- Tests (56 synthetic + 2 real-data), names carry requirement IDs; fixtures `spec-example.csv`
  (the format doc's example), `patterns.csv`, `pairing.csv`. A balance test checks that the rows'
  account effects reproduce every account balance computed straight from the legs.
- Real export (`.realData`, counts only): 4 887 transactions → 3 923 rows: expense 2 081
  (refunds 27), income 99 (reversals 10), transfer 1 428 (of which **964 paired from halves**),
  opening balance 35, unpaired halves 280; 0 skipped; 24/24 account balances match; row warnings:
  unbalanced 11, transfer to self 2, estimated split 1, refund record 1.

## Blockers / contract-change requests (for the orchestrator)
1. **`NormalizedLine` has no refund flag.** A transfer with a CREDIT EXPENSES leg (1 in the real
   file) is emitted as an attached `.income` line whose category is the *expense* category, note
   "Refund", plus a row warning. A refund or income reversal split over several categories (none
   in the real file) is collapsed onto the first category with a warning. Proposal: add
   `isRefund: Bool = false` to `NormalizedLine` (and to the attached-record entity if A1/A5 need
   it); then the parser emits refund lines properly.
2. **Minor units of non-account currencies.** `OriginalAmount.minorUnits` has no shared exponent
   rule; the parser uses ISO 4217 exponents (2 by default, 0 for JPY/KRW/…, 3 for BHD/KWD/…) in
   `Saldo/SaldoLeg.swift` (`MinorUnits`). A shared helper in `AbacusDomain` would keep A4/A6/UI
   consistent. Low priority (the real file only has 2-decimal currencies).
3. **Opening-balance sign convention** (for A1/A6): `.openingBalance` amounts are signed
   debit-positive, the same way transfers move money (to-account +, from-account −). A liability
   with an initial debt therefore gets a negative opening balance. The real file has none on
   liabilities.

## Spec gaps (docs/import/saldo-format.md) — no real names or amounts
- **Pairing rule vs. the 961 figure.** Plain "closest first" with the "accounts differ" rule
  pairs only 871 on the real file: chains (USD account → UAH account → card, booked seconds
  apart with the same transit amount) make a half's closest candidate its own account's other
  half, which is not allowed, and greedy strands both. A maximum matching under the same three
  rules gives 964 (≈ the doc's 961, which was evidently counted without the account rule). The
  doc's wording "choose the closest" should become "most pairs; among them the closest".
- **Cross-currency halves with different transit currencies.** Of the 280 unpaired halves,
  ~85 outgoing/incoming pairs are cross-currency transfers where each half books the MOTW leg in
  its own account's currency, within 2 minutes of each other, different accounts. Rule 1 (equal
  transit currency) excludes them, so they go to needs review. An optional second pass (transit
  currencies differ, different accounts, ≤ 2 minutes, closest first) would pair them — owner
  decision; not implemented.
- **Patterns not in the table** (all handled): CREDIT asset + CREDIT EXPENSES + DEBIT asset (1,
  see request 1); 2 × CREDIT INCOME + DEBIT asset (1, income split); CREDIT asset + DEBIT asset of
  the **same** account (2, kept as a transfer to itself with a warning); split whose expense legs
  are in two different foreign currencies (1, divided equally with a warning).
- Tags: in 230 transactions the tag is on some legs only (e.g. only the expense leg); never two
  different tags. Notes may contain line breaks (4). Neither is mentioned in the doc.
- MOTW "Account" names: in same-account chains the hint often names an unrelated account —
  confirms the doc's "not reliable"; the parser passes it only as `counterpartHint`.
