# C45 — Import sheets and dialogs: "Find the other side", Move label, moved alert

State: done (awaiting merge)   ·   Branch: wp/C45-sheet-dialogs   ·   Updated: 2026-11-01

Owner feedback on 1.6.0. Each item has a test that failed before the fix, plus an in-app snapshot on a
scratch database with sample data (`docs/status/C45-screens/`). No real data was used.

## S1. "Find the other side of the transfer" showed an empty list

**What the owner saw.** "No transactions on “PKO $ Firma” from 30 Sep 2026 to 10 Oct 2026" with an empty
list and an empty search.

**Root cause.**
- The query itself is fine. With stored transactions on the other account it lists every one of them
  for an empty search: stored income, expense and transfers, any direction, the ones it can't use greyed.
  I reproduced this in a test and in the app (`counterpart-sameday.png`: the stored "Currency exchange"
  transfer on PKO USD is listed on the transfer's day). The search covers stored transactions of the
  chosen account only. Rows of the file being imported are not searched, because they are not stored
  yet. There is no currency filter, and direction is not used as a filter.
- So the owner's empty list most likely means the account really had nothing stored in those 11 days.
  The likely reason is that the "PKO $ Firma" statement for October is not imported yet. I did not open
  the owner's database to confirm this.
- A real bug made it worse: a stored transaction that another row of the same import already used
  (settled, linked or taken over) was **left out of the list without any sign**
  (`counterpartOptions(…from:through:)` filtered `touchedExistingTxnIDs`). The account could look
  empty when it wasn't.
- The default window was ±5 days. The owner wants the transfer's day by default.

**Fix.**
- The default window is now the transfer's day (from = to = the row's date) on every path: review
  "Transfer to my account", popup Save, "Change…", bulk, and popup "Change transaction". The date pickers
  still widen it.
- An empty list (empty search) now offers **"Widen to ±5 days"**, plus **"Other accounts with
  transactions in these days"** as one-click links ("Alex Example (PLN) · 1"). A link switches the
  sheet to that account.
- Transactions another row already uses stay listed, greyed, with "Another row of this import already
  uses it." (`ImportCounterpartOption.isTakenByAnotherRow`). The row's own taken-over transaction stays
  usable in its "Change…".

**Verified.**
- Tests `ImportCounterpartSheetTests`:
  - "with an empty search the sheet lists every stored transaction of the account on the transfer's
    day": failed before the fix (window ±5, next-day row listed).
  - "a transaction another row of this import already takes over stays listed, greyed with the
    reason": failed before (the list was empty).
  - "an empty day offers Widen to ±5 days and the accounts that have transactions that day": failed
    before.
- Existing tests were updated to the same-day default: `ImportCounterpartTests.findTheOtherSide` /
  `refusedCandidate` and `ImportTransferPopupTests.emptySearchListsAll`.
- Snapshots: `C45-screens/counterpart-sameday.png` (stored transaction listed, empty search, window
  25/9–25/9) and `C45-screens/counterpart-emptyday.png` (empty day: Widen button and other-account link).

## S3. "Move to another account…" → "Move to another account"

**Root cause.** The button label in `ImportView.swift` (History) had an ellipsis. Comments elsewhere
did too.
**Fix.** The label is `ImportWizardModel.moveActionTitle = "Move to another account"`. Comments are
updated in the AbacusFeatures, AbacusStore, AbacusImport and test files. The sheet is unchanged.
**Verified.** `ImportMoveTests.undoMoveAndUndoImport` asserts the title. Snapshot
`C45-screens/history.png` shows History with "Move to another account" and no ellipsis.

## S4. "Transactions moved": OK is the default, "Undo move" plain

**Root cause.** The alert listed "Undo move" first. On macOS the first alert button is the default
(blue).
**Fix.** The buttons come from `ImportWizardModel.moveNoticeButtons`: OK first (default,
`.keyboardShortcut(.defaultAction)`), then Undo move while the move can still be undone. "Import undone"
only has OK, so it needed no change.
**Verified.** `ImportMoveTests.undoMoveAndUndoImport` checks the order `["OK", "Undo move"]`, the
defaults `[true, false]`, and only `["OK"]` after undo. Snapshot `C45-screens/move-alert.png` shows a
blue OK and a plain Undo move. Undo move still carries the system keyboard-focus ring, which macOS adds
for Tab navigation; it is not the default.

## UI check hooks (DEBUG)

`-AbacusImportFile <csv>` now also takes:
- `-AbacusImportDemo counterpart:<account>`: opens "Find the other side…" for the first row that needs
  it.
- `-AbacusImportDemo moved:<account>`: imports, moves the batch and shows the alert.
- `-AbacusImportDemo history:<account>`: imports and opens History.
- `-AbacusImportTarget <account>`: the statement account.

A demo waits for the sample data's accounts first. Run it with `-AbacusDatabasePath <scratch>
-AbacusLoadSampleData YES -AbacusSection importFiles` and `CFFIXED_USER_HOME=<scratch>`.
