# S1 — Stability and performance (D54)

Branch `wp/S1-stability`. Owner testing of 1.2.0 on real data: crashes on Escape, after drag and
drop, after saving a debt record (Forgive); hangs ending in Force Quit; Accounts slow to open.
Stability and performance only — no features.

## Root causes found

1. **Crash: force-unwrapped bindings to optional drafts** (all three 1.2.0 crash reports,
   `BindingOperations.ForceUnwrapping.get`). `DebtsView` built its forms with
   `Binding($model.debtDraft)` / `Binding($model.recordDraft)`. Save, Delete, Cancel and Escape
   set the draft to nil while the sheet's fields were still alive (dismiss animation), and the
   next read of a field's binding trapped. Reproduced on the old code with the soak run below
   (identical stack in `~/Library/Logs/DiagnosticReports`); gone after the fix.
   Fix: `presentBinding` (App/macOS/Shell/SafeBindings.swift) reads the live draft or the last
   shown one and drops writes once the draft is gone.
2. **Crash risk: `ForEach($model.lines)`** in the transaction editor's fee/split lines (index-based
   bindings; removing a line while its field is focused can read a stale index). Now `ForEach`
   over values with `elementBinding` (by id, fallback when gone).
3. **Crash risk: `CategoriesModel.plan`** appended to `blocks[blocks.count - 1]` when a child came
   first; guarded.
4. **Double save** of a debt record/debt (Return pressed twice, Save then Delete): `DebtsModel`
   now runs one write at a time (`isSaving`, Save disabled while saving). Soak: a double save adds
   one record.
5. **Hangs / slowness: `Day` and `Month` compared by formatting strings.** `Day.<` built two
   `String(format:)` per comparison; every balance-through-a-day loop, the net-worth series
   (12 passes over all effects), date filters and sorts paid that on the main actor. Net worth on
   5,000 transactions took 195 ms of a 327 ms dashboard load (release). Now compared by numbers
   (same order; test `dayOrderMatchesStrings`). This is a change in `AbacusDomain` (shared file).

Not found: no `.onChange`/`onDataChange` → reload → state change → reload loop; no rate-refresh
loop; no Task storm. The save cascade (editor/debt save → transactions, dashboard and every
loaded manage screen reload) runs once per save; with the `Day` fix each reload is cheap (below).

## Audit checklist (App/macOS, AbacusFeatures)

- [x] `Binding($optional)` — only DebtsView (2 sites), fixed.
- [x] `ForEach($array)` / `$items[i]` index bindings — only EditorLinesSection, fixed.
- [x] `!` force unwraps reachable from view bodies — none in App/macOS (previews only); in models:
  `debts[0]` (groups never empty), `parentID!` after `isChild`, `max()!` on non-empty arrays — safe;
  `blocks[blocks.count - 1]` fixed.
- [x] Sheet/inspector content reading state another path clears: Accounts, Categories, Events,
  Rules inspectors/editors use `draftBinding` (safe fallback); manage dialogs use
  `sheet(item:)`; transaction editor owns its model in `@State`; Import review Cancel calls
  `model.cancel()` (no optional binding); Budget fields use get/set closures.
- [x] Escape (`.cancelAction`, sheet dismiss) on: Transactions editor, Debts (debt + record),
  Rules sheet, Categories, Accounts, Events, Budget, Import — all go through safe bindings now.
- [x] Lifecycle: `.task(id: model.query)` (query is stable), `.onChange` handlers only set values;
  `sectionAppeared` reloads once per switch.
- [x] Accounts/Categories drag hover (`canDrop` per mouse move): 0.7 ms (release) on 50 accounts;
  the view files belong to S2 (rewritten there).

## Tools added

- `LargeSampleData` (AbacusFeatures/App): deterministic synthetic set — 5,000 transactions over
  30 months, 50 accounts in 8 groups (some archived), 40 categories, 8 events, a budget, 40 rules,
  10 debts with records, daily rates. Test fixture and DEBUG launch option
  `-AbacusLoadLargeSampleData YES` (empty database only).
- `StabilityProbe` (App/macOS/Shell, DEBUG or `-DABACUS_PROBE`): `-AbacusHangWatch YES` prints
  `HANG <ms>` when the main thread is blocked > 100 ms; `-AbacusSoak YES [-AbacusSoakRounds n]`
  switches every section, saves/double-saves/cancels debt forms (Forgive), opens and closes the
  editor, drags an account and a category, then quits. Scratch databases only.
  Optimised probe build:
  `xcodebuild … -configuration Release -derivedDataPath build.noindex/relprobe 'OTHER_SWIFT_FLAGS=$(inherited) -DABACUS_PROBE' build`.
  Note: sheet open/close animations run AppKit's own loop, so the watch also reports them
  (~250–580 ms during the Debts/editor steps); those are not model work (`sample` shows
  `NSMoveHelper _doAnimation`).
- Tests: `LargeDataPerformanceTests` (load budget 150 ms in release / 1.5 s debug; body reads
  5 ms / 30 ms), `StabilityTests` (double save, cleared drafts, reload idempotence, day order).

## After merging S2 and S3

- Re-audit on the merged tree: no `Binding($…)`, `ForEach($…)` or force unwraps in App/macOS;
  S2's Accounts/Categories editors keep non-optional `@State` drafts (`ManageEditorSheet`).
- Outline list (S2): `validateDrop` runs on every mouse move and asks `canDrop`. The models now
  answer each (moving, target, position) once until accounts/groups/categories/sort change
  (`dropChecks`), so a drag does no tree work per move. `updateNSView` reloads only when the
  row keys change (S2's own check).
- A drop no longer runs a full `load()` (all transactions, balances, usage counts): it re-reads
  only the accounts and groups / the categories (`reloadOrder`); balances and counts stay.
  Test `dropRefreshesOrderOnly`.
- Soak on the merged optimised build (2 rounds): no crash, a double save adds one record;
  accounts section switch ~200 ms (was 269 ms), dashboard 47 ms. Snapshots of Accounts and
  Debts on the synthetic set render normally.

## Remaining risk
- Manage screens still read every transaction for balances/usage counts (fine at 5,000; SQL
  aggregates would be the next step for 20k+).
- Save cascade reloads every loaded screen sequentially; fine now, could be coalesced.
