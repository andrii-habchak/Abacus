# C37 — Account picker with search, Accounts filter search, Edit rule layout

Branch `wp/C37-account-picker`. Owner feedback from 1.5.0: every account selector needs search like
the category ones; the Transactions Accounts filter needs a search; the Edit rule sheet is broken.

## Done

- `AbacusFeatures/Shared/AccountSearch.swift` (pure, tested in `AccountSearchTests`):
  `AccountPickerItem` (id, name, currency code, group name as `section`, `isArchived`, optional
  `customTitle`; `title` = "Name · CUR"), `AccountPickerItem.items(from: [AccountPickerSection])`.
  `AccountSearch.items/groups(_:query:isSelected:excluding:)`: folding is `RulePattern.normalized`;
  matches name, currency code or group name (a group-name hit shows the whole group); archived rows
  dropped unless `isSelected`; `excluding` drops accounts always; empty groups vanish.
  `AccountSearch.sections(_:query:isSelected:)` is the multi-select variant (ticked accounts stay).
- `App/macOS/Shell/AccountPicker.swift`: `AccountPicker(items:|sections:, selection: Binding<Account.ID?>,
  excluding:, noneTitle:, placeholder:, fixedTitle:, width:, accessibilityTitle:)`. Same popover as
  `CategoryPicker` (focused search, up/down/return, group headings, none row `noneTitle`).
- Converted single-select account selectors (the old `AccountPickerItems` helper is deleted):
  Import "Import into" (PKO); import review card transfer account ("Other account", flat list
  before, now grouped); import bulk bar "Account" (`fixedTitle: "Account"`, only that control);
  import Mapping tab account rows ("Map X": "Create …" is the none row, archived accounts stay
  offered with an "(archived)" suffix); rules editor "Account is" condition and "Transfer to/from
  account" action; transaction editor Account, From, To (`EditorAccountPicker`).
- Not converted on purpose: Debt link sheet "Account" (the person's accounts plus "New virtual
  account", a handful of rows, not own accounts); Debts "Add accounts" (already a searchable list);
  Accounts editor "Group" (account groups, not accounts); the Accounts filter of Transactions is
  multi-select (below). PKO "no account yet" prompt buttons are buttons, not a picker.
- Transactions filter Accounts popover: search field above the list (`AccountSearch.sections`);
  groups with no hit disappear; ticked accounts always stay; "No account matches." note.
- Edit rule sheet (`RuleEditorSheet`): the cause was content wider than the sheet (action row =
  action menu + kind menu + 200 pt category picker > 476 pt) — SwiftUI centres an over-wide child,
  so both edges were clipped. Now: fixed width 560 pt with `.topLeading` alignment, title row and
  every block `maxWidth: .infinity` leading, the action menu (and kind) on one line and the target
  picker (category / account / debt) on a full-width second line, captions wrap (`fixedSize` vertical).

## Interpretations

- The exclusion hook is provided (`excluding`) but not wired to the editor: From/To of a transfer
  stay unrestricted as before (validation already rejects the same account).
- Group-name search also matches "PKO" typed in the filter list, so a group heading hits all members.
- The "Ł" letter does not fold to "L" (`RulePattern.normalized` uses diacritic folding only).

## Not verified (no UI access)

Popover sizes and focus, button widths in the import header/cards/mapping rows, the bulk bar button
look (bordered, small), and the Edit rule sheet in all three action variants and the new-rule sheet.

## Proposed requirement text

R-UI-ACCSEARCH: Every account selector offers a search field (focused when it opens) that matches the
account name, its currency code or its group name, ignoring case and diacritics; a matching group shows
all its accounts. Accounts stay grouped under their group headings; archived accounts are hidden unless
chosen. The Transactions Accounts filter has the same search; ticked accounts stay visible.
R-UI-SHEET: Sheets lay out in a fixed width with equal insets; no control may widen a sheet past it.
