## Done
- App icon: `App/macOS/Assets.xcassets/AppIcon.appiconset` (all macOS sizes, 16–1024 px), drawn
  by `scripts/make-icon.swift` (CoreGraphics, no third-party assets); `ASSETCATALOG_COMPILER_APPICON_NAME:
  AppIcon` in `project.yml` (xcodegen already wrote it into the project by default, so the
  regenerated `.xcodeproj` only changes `MARKETING_VERSION`); `MARKETING_VERSION` 1.0.0.
- `scripts/build-dmg.sh`: xcodegen generate, Release build (universal arm64 + x86_64, ad-hoc
  signed, `-skipMacroValidation`, `codesign --verify`), `dist/Abacus-<version>.dmg` with the app
  and an `/Applications` link via `hdiutil` (UDZO), SHA-256 printed and written next to it;
  `dist/` is ignored. First run: `dist/Abacus-1.0.0.dmg`, 18.4 MB, about 3 minutes.
- README screenshots `docs/screenshots/` (1600 px wide; Settings at 2x): `dashboard`,
  `dashboard-dark`, `transactions`, `accounts`, `budget`, `import` (step 1), `rates`,
  `settings-general`. Debug app, in-app snapshot (`WindowSnapshot`), a temporary database
  seeded by Load Sample Data, live NBU rates. Every launch also ran with `CFFIXED_USER_HOME`
  pointing at a scratch folder: `AppBootstrap.prepare()` opens the **default** database before
  `-AbacusDatabasePath` is read (see blockers), so the fake home kept the real one closed; its
  files' timestamps were unchanged afterwards. The editor sheet has no launch option, so it is
  not shown.

## Blockers / contract-change requests (for the orchestrator)
- **`AppBootstrap.prepare()` always opens the default database**
  (`~/Library/Application Support/Abacus/abacus.sqlite`, with migrations) as `defaultDatabase`,
  even when `-AbacusDatabasePath` or `-AbacusPreviewData` is passed. Any screenshot or test
  launch therefore touches the real file. Suggested fix (app/Features lane): resolve the launch
  options first and open only the chosen database.
- **Import section grows the main window**: opening Import made the window about 2,250 pt tall
  (beyond the screen) and the size was saved in the window frame autosave, so later launches
  opened too tall. The README capture was fitted to the normal 860 pt window height (top-aligned
  content plus the sidebar's bottom strip). Likely cause: the import page's content height
  propagating to the window (`App/macOS/Import/ImportView.swift`); worth a look in a UI lane.
- Screenshot launches share the app's preferences domain (`io.github.andrii-habchak.Abacus`), so
  window frames from test launches reach the real app; the main window frame was reset to the
  default 1280 x 860 afterwards.
