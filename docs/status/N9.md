# N9 — Events UI requests (owner review of 1.7.0)

Branch `wp/N9-events-ui`.

## Done
1. **Event editor is a sheet** (same `ManageEditorSheet` chrome as accounts and categories: title,
   fields, Archive / Unarchive + Delete… bottom-left, Cancel + Save / Create bottom-right, Escape =
   Cancel, Return = Save while valid, validation message after the first edit). Opens by
   double-click / Return / context menu "Edit…" and from "New event". All fields kept: name,
   Starts / Ends, budget + currency, Spent card with category bars, colour + custom colour,
   default-tagging note, "Show N transactions" (closes the sheet, then opens Transactions),
   read-only archived event (colour stays editable). Archive and Delete… close the sheet;
   Delete… keeps its confirmation (shown on the sheet). Inspector pane removed, the list uses the
   full width. Model: `EventsModel.sheet`, `edit(_:)`, `dismissSheet()`, `save(_ draft:)`,
   `validationMessage(_:)`, `isDirty(_:)`, `canSave(_:)`, `isReadOnly(_:)`; `EventDraft` is now
   `Identifiable`; old draft-property API still works.
2. **Row buttons**: Archive (`archivebox`; `tray.and.arrow.up` + "Unarchive" on an archived row
   under "Show archived events") and Delete (`trash`) at the end of each row, secondary colour,
   tinted rounded background (accent / red) on hover, tooltips. Plain buttons: a click on them does
   not select or open the row. The list is single-select (no multi-select exists). Accounts and
   categories have no hover actions to follow. Model: `archiveOrUnarchive(_ id)`,
   `requestDelete(_ id)`, `archiveTitle(for:)` work on the row's event, not the selection.
   Delete uses the existing confirmation. Archiving still turns "Show archived events" on (existing
   behaviour) so the row stays visible.
3. **Toolbar**: `ToolbarSpacer(.fixed, placement: .primaryAction)` before "New event" / "New
   category" makes each its own glass pill next to "New transaction" (Accounts gets this from its
   `Menu`). Checked light/dark in the snapshots.
