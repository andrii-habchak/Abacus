## Done

- **Native outline list** (`App/macOS/Manage/OutlineList/OutlineList.swift`): one
  `NSViewRepresentable` around an `NSOutlineView`, used by Categories and Accounts. Standard macOS
  drop feedback (`draggingDestinationFeedbackStyle = .regular`): a line between rows = reorder, a
  highlighted row = drop onto (nest); auto-scroll while dragging and scrolling after a drop are
  the outline's own (an `NSScrollView`, no SwiftUI `List` drop zones). Rows keep their SwiftUI
  content (hosted per cell, clicks pass through to the outline). Selection, double-click / Return
  / context menu "Edit…" open the editor. Groups / parents are expandable (collapsed state kept
  across reloads). The old "top / bottom 28 % of a row" delegates are gone.
  - Why `NSOutlineView` rather than `List` + `.onMove` + `.dropDestination`: the outline gives
    the level-aware gap line (dropping after a group's last child vs between top-level rows),
    "onto" highlighting and auto-scroll natively; `List` has no "onto" feedback and was the
    source of the lost-scroll and crash reports.
  - Crash-proofing by construction: items are reference objects rebuilt only when the rows'
    content changes (Hashable signature); every data-source lookup is bounds-checked; the
    outline never changes data, it asks `canDrop` for every proposal and calls `onDrop` on the
    next run-loop turn, after the drag session has finished (the model then reloads the list).
    Only rows of the same list can be dropped (private pasteboard type, local move only).
  - Proposal mapping is `AbacusFeatures/Manage/OutlineDropResolver.swift` (AppKit-free, unit
    tested): onto a row; child index of a parent → before that child / after the last one / onto
    an empty parent; top level → before a root (never above the pinned Uncategorised) or the end
    (top level, last). When "onto" is refused (a parent with subcategories, a group onto a row)
    the outline retargets to the gap above / below the row under the pointer.
- **Drop rules** (models, unchanged API, still `drop(_:on:position:)` / `canDrop`):
  - Categories: between rows = reorder (sort → Custom order); onto a top-level category =
    subcategory (same kind, a category with children can't nest); a subcategory between
    top-level rows = top level; Uncategorised pinned, not draggable, not a target.
  - Accounts: between = reorder; onto a group = into it; onto an account inside a group = join
    that group; **onto an ungrouped account = new group of both** — `drop` sets `groupPrompt`
    (suggested name = the target's first word), the page shows a name sheet, then
    `confirmGroupPrompt(name:)` creates the group in the target's place (target first, then the
    dragged account; the sort stays); Cancel / `cancelGroupPrompt()` changes nothing. Dragged
    out between top-level rows = ungrouped.
  - **Empty groups stay** after their last account moves out (D48: folders the user deletes;
    silently deleting a named folder seemed more surprising). The row then reads "0 accounts".
- **Editors as sheets** (`ManageEditorSheet` in `OutlineList/`): categories (new / edit /
  Uncategorised colour), accounts (new / edit), groups (new / edit). Title, fields, then a footer:
  Archive… / Unarchive / Delete… on the left, Cancel + Save / Create bottom-right (R-MGMT-10);
  Escape = Cancel, Return = Save while valid. Each sheet holds its draft as non-optional `@State`
  and hands it to the model on Save (`save(_ draft:)`); no `Binding($optional)` anywhere. The
  models gained `sheet` (what is open), `edit(_:)`, `dismissSheet()` (a cancelled new item gives
  the previous selection back), `save(_:)`, and draft-taking `validationMessage(_:)`,
  `isDirty(_:)`, `canSave(_:)`, `isCurrencyLocked(_:)`, `parentOptions(_:)`,
  `canChangeParent(_:)`, `usageText(_:)`; the old draft-property API still works (`save()` now
  returns a discardable Bool). Confirmations from inside a sheet show as a sheet on the sheet;
  archive / delete close the editor. The lists take the full width (inspectors removed).
- **"New account" split button** (toolbar `Menu` with `primaryAction`): the main part = new
  account (prefilled with the selected row's group, as before — visible and changeable in the
  sheet); the menu lists "New account in <group>" for each group A–Z
  (`newAccount(currency:inGroup:)`), then "New group…". The "New group" icon in the filter row
  is gone (it lives in the menu).
- **New transaction on the selected account**: `TransactionEditorMode.newInAccount(id)`,
  `AppModel.newTransactionAccount` hook next to C10's category hook (set by `AppSession` while
  the section is Accounts and a non-archived account is selected); the editor applies the usual
  defaults, then that account and its currency.
- Search, sort selector, currency filter and "Show archived accounts" unchanged and feeding the
  outline.
- DEBUG launch option for UI checks: `-AbacusOpenSheet newAccount|editAccount|newGroup|editGroup|
  groupPrompt|newCategory|editCategory|editUncategorised` (waits for the page's rows).
