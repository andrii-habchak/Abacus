# B2 — Dashboard
State: done (on preview data; wiring by the orchestrator)   ·   Branch: wp/B2-dashboard   ·   Updated: 2026-10-21

Builds the approved Dashboard (`docs/design/1-dashboard.dc.html`, README § 1) on the A1
calculators and the repository protocols, with in-memory fakes over `PreviewData`.

## Done

## Wiring notes (orchestrator)

## Choices to confirm with the owner
- Budget amounts are shown in the display currency (R-HOME-4) at one rate: latest for the current
  month, the month's last day for a closed month; ok/near/over is decided in the plan's currency
  (R-BUD-2), so switching currency never changes a status. A note under the bar says so.
- Budget bars are drawn bars, not `ProgressView`: a linear `ProgressView` turns grey in an inactive
  window and would hide the over/near colours.
- The "Uncategorized" donut slice is selectable but does not drill down (no `TxnQuery` filter for it).

## Blockers / contract-change requests (for the orchestrator)
1. **Calc (A1): a zero amount needs no rate.** `Calc.convert` records a missing rate for a balance
   of 0 (e.g. accounts before their opening day), so `NetWorth.unconverted` over-reports. Worked
   around in `DashboardNetWorth.make` (only non-zero balances without a rate count). Request:
   `if minor == 0 { return 0 }` in `Calc.convert`.
2. **TxnQuery: an "uncategorized" filter** (e.g. `includeUncategorized: Bool`) so the donut's
   Uncategorized slice can drill down (R-HOME-3). Low priority.

## Deferred
- Performance on 20k transactions (R-NF-2): the model loads every transaction up to today once per
  load and runs the calculators in memory; if it is slow, switch the net-worth series and month
  totals to A5's `SQLiteReportQueries`.
- No UI test of hover/click (Swift Charts interaction); covered by model tests of `select(_:)`.
