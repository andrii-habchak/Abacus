## Done

1. **Drop hint** on the Done step: dashed "Drop a CSV export here / to import the next file" box under the buttons
   (highlights while a file is dragged over the window).
2. **Category refresh and "+ New category…"**
   - `ImportWizardModel.refreshReference()` re-reads accounts and categories and also refreshes the open preview's
     category context (`ImportPreview.refreshCategories`), so a pick of a new category is learnable as a rule.
     Called from `ImportView` on appear and when the app becomes active, and from `AppSession.referenceChanged()`
     (one added line: a category created/edited on the Categories page reaches the wizard at once).
   - Row category pickers (Transactions tab, review cards) end with `+ New category…` (`ImportCategoryChoice.createNew`).
     It opens a sheet (name, kind fixed from the row, optional parent); the category is created, categories reloaded
     and it is selected for that row. Same name + parent as an active category = that category is used (no duplicate).
     The picker in `ImportRowsTab` is unchanged apart from the extra option, so the C34 control swap stays simple.
3. **Category assignment tab** (`Tab.categoryAssignment`, "Category assignment (N)", N = rows needing a category).
   Plain click selects one row, Cmd+click toggles, Shift+click ranges from the last clicked row
   (`ImportWizardModel.select(_:mode:)`, `importSelect` reads the modifier keys). Selection is cleared when the tab or
   card filter changes and rows that leave the list are dropped from it. Works on the Transactions tab (all filters)
   and on the Needs review cards (click the card title).
4. **Bulk bar** above all three lists: Category, Account, Debt…, Skip (+ Include for rows skipped here), Clear,
   Undo of the last bulk step.
5. **Rule suggestions sheet** after a bulk Category (`ruleSuggestions(forRows:)`, `applyRuleSheet`).

## Interpretations (please confirm)

- **Mixed income/expense selection:** the bar shows two menus, "Expense category" and "Income category"; each sets
  only the rows of its kind. A single kind shows one "Category" menu. Needs review rows count by their sign
  (money in = income) and are recorded as that kind with the category.
- **Bulk Account** on a new expense/income row is a *new import decision* (`ImportPreview.setTransfer(toAccount:)`):
  money out becomes a transfer to the account, money in a transfer from it, like a transfer rule (D44). It needs the
  amount on the other account: same currency, or the file's original amount in that currency; rows that cannot
  (same account, unknown amount, incoming rows with attached records) are skipped and counted in the message.
  Needs review rows use their existing "Transfer to my account" choice.
- **Bulk Debt** opens the existing debt sheet on the first selected row (amounts shown are that row's); the chosen
  person/debt/account applies to every selected row that can be a debt record. The typed amount on the person's side
  (only needed across currencies) is used for the first row only; the others are converted at the day's rate or use
  the file's original amount, otherwise the existing "amount unknown" issue blocks the import as for a single row.
- **Bulk Skip** is a new decision too (`setExcluded`): a new row is left out (status Skipped, "Skipped by you", with
  an Include button); a possible duplicate gets action Skip; a Needs review row gets the Skip choice. Rows already
  skipped, imported or settling are untouched.
- **Rules:** a bulk Category pick behaves like today's single pick: rows with no file category and no matching rule
  get a learned rule by default. The sheet lists one rule per distinct derived pattern and category, ticked, pattern
  editable (>= 3 characters). "Save rules" unticks/edits (`ImportPreview.setRulePattern`, `setSavesRule`); "Not now"
  leaves the defaults (all saved). Payees with an enabled rule never get a learned pattern, so they are not offered
  (including when the rule gives another category). Needs review rows get no rule (as before).
- One-step undo of a bulk action restores the whole preview as it was before it (any later edit clears the undo).

## Pipeline changes (AbacusImport)

`ImportPreview`: `batch(_:)` (one recompute for many edits), `refreshCategories`, `setExcluded`, `canTransfer`,
`setTransfer(toAccount:)`, `setRulePattern`, `derivedRulePattern`; `PreviewRow.excludedByUser`. A user transfer wins
over rules and debt decisions; setting a category or a debt on the row replaces it.

## Proposed requirement text (for the orchestrator, TA R-IMP)

- R-IMP-9 (proposed): The review lists support multi-selection (click, Cmd+click, Shift+click). A bulk bar sets the
  category, makes the rows transfers to an own account or a debt account, or skips them; one step can be undone.
- R-IMP-10 (proposed): "Category assignment" tab lists the rows that need a category, with their count.
- R-IMP-11 (proposed): After a bulk category the app offers the learned rules, one per payee pattern, ticked and
  editable. Row pickers offer "+ New category…" and always list the categories that exist now.
