# C40 — Import: transfer popup, account and dates in "Find the other side…"
State: done (awaiting merge)   ·   Branch: wp/C40-transfer-popup   ·   Updated: 2026-11-01

Owner requests (Import page, transfers), all three built:

1. **Account in "Find the other side…"** (C38 sheet). A searchable account picker (the shared C37
   `AccountPicker`) chooses the account the other side lives on; title, currency of the typed amount
   and the NBU estimate follow it. Default: the transfer's current other account (the account the
   sheet was opened for). Offered: every active account except the row's own.
2. **No empty list without a search.** The sheet has a date window (From / to date pickers, default
   ±5 days around the row as before). With an empty search it lists ALL transactions of the chosen
   account in the window; a search text filters them by description, note and amount. Transactions
   that cannot be the other side stay listed but greyed with the reason (refusals from C38, and new:
   "Money moves the same way as this row, so it can't be the other side."); usable ones come first.
3. **Transfer popup.** Double-clicking a transfer row in the Transactions tab opens a sheet:
   - **From / To** account pickers. The statement's side (the file's account: From for money out, To
     for money in) offers only accounts in the statement's currency (the row's amount is in it); the
     other side offers every active account. Save applies both; the same account on both sides, or a
     statement side in another currency, is refused with the reason in the popup.
   - **Related to**: what made the row a transfer and what it is tied to — the transaction it takes
     over (C38 absorb), a transaction imported earlier from the other account that it completes, an
     amount typed or estimated (C38), two paired halves of a Saldo file, a row paired in Needs review,
     the other account recognised by its number (PKO), a transfer rule, or "chosen by you".
   - **Change transaction…**: opens "Find the other side…" for the other account with the window
     set to the transfer's day (both date pickers = that day). Opens inside the popup; after a pick
     the popup shows the new state.
   - Under From and To: the transactions of that account on the transfer's day — rows of this file
     ("In this file", the row itself marked "This transfer") and transactions already stored ("…
     already in Abacus", the one the transfer takes over marked "Becomes this transfer").
   - When the new other account is in another currency and the file does not give the amount there,
     Save opens "Find the other side…" for it (find, type or estimate, as in C38).

## How the link is stored (C38, for reference)
The row's other side is a preview decision (`Decisions.counterparts[rowID]`: `.existing(Txn)` /
`.manual` / `.estimated`); a found transaction becomes `PreviewRow.absorbedTxn` and a `.convert` plan
(the commit converts it in place, `importTxnSnapshots` keep it for undo). A transaction already imported
from the other statement that the row completes is `RowAnalysis.completesTransfer` (also `.convert`).
The popup reads both through `ImportPreview.transferRelations(forRow:)`.

## Interpretations (please confirm)
- "Change the From and To": the statement's side can move only to an account in the statement's currency
  (the row's amount is in that currency; another currency would need a second unknown amount). The other
  side can be any active own account.
- Changing the statement's side does not re-run duplicate detection for the new account (dedupe was done
  for the file's account); the row keeps its fingerprints.
- The search no longer widens to ±60 days by itself: the date pickers set the window, the search filters
  within it.
- "All transactions" includes those moving money the same way as the row and those C38 refuses (already a
  transfer, attached records…), shown greyed with the reason and not choosable.
- "Related transactions" under each account = the transactions of that account on the transfer's day
  (this file's rows and stored ones).
- The popup opens only for rows this import turns into a transfer (new transfer, Needs review row with a
  transfer choice, a row that takes over/completes a transaction); not for already imported, skipped,
  debt or "completes an estimated transfer" rows. "Change transaction…" is disabled while the draft has
  unsaved account changes.
- Changing the other account of a PKO row recognised by its number drops the automatic "completes the
  transaction imported from the other statement" when that transaction is on the old account.
