## Done
- `AbacusFeatures/Editor/` (platform-neutral):
  - `TransactionEditorModel` (`@Observable`, main actor) over the repository protocols:
    one form for Expense / Income / Transfer (R-EDIT-1, R-TX-1); fields as bindings with the
    prototype's side effects (changing amount, currency or account re-estimates the charged
    amount; changing the type clears Refund and an unmatched category).
  - Defaults (R-EDIT-4/5): a new transaction starts with `lastTxnCurrency` + `lastAccountID`,
    a new transfer with `lastTransferFromID/ToID`; unknown or archived accounts fall back to the
    first active account; the hint shows only when a remembered value was used and until the
    user changes currency/account/From/To. Saving a **new** transaction (or a duplicate)
    remembers them; editing does not.
  - Transaction currency (R-CUR-4, R-EDIT-4): picker with UAH, PLN, EUR, USD, CHF, CZK, GBP,
    HUF (+ the stored code when another); "Charged to account" when it differs from the
    account's, pre-filled at the day's rate from the `CurrencyConverter` and editable. D24: no
    pre-fill for codes without rates ("No rates for HUF in Abacus…"), nor before the first
    known rate. Saved as `amountMinor` = charged, `originalAmountMinor/CurrencyCode` = typed.
  - Refund / Reversal (R-TX-4), sign − / + / ⇄; transfer From/To with "From and To must be
    different accounts.", "Amount received" + implied rate across currencies (R-TX-5).
  - Category picker (parents with indented children, archived hidden) with the rule suggestion
    (R-EDIT-3, R-IMP-8): first enabled rule, in repository order, whose pattern is contained
    case-insensitively in the description, with a matching optional account and an active
    category of the right kind; applies until the user picks a category. Saving with the
    suggested category records a rule hit.
  - Event (R-EVT-2): the event active on the date (start ≤ day ≤ end, open end allowed; latest
    start wins) is pre-selected for a new expense/income with "Pre-selected: “X” is active on
    this date"; follows the date until the user picks one (None clears it). Not for transfers
    or edits. Labels "Lyon trip · 1–19 Oct".
  - Lines (R-EDIT-2, R-TX-6): Add fee (Fees, note "Fee"), Add line (the main category for an
    expense); kind switch resets the category (Fees / Cashback); income lines also offer
    expense categories as refund lines (D22); "Effect on <account> [in CUR] (with N lines)" =
    main ± lines in the account currency.
  - Validation (Save disabled until valid): positive amount, account, charged amount when
    foreign, category of the matching kind, To account, different accounts, amount received
    across currencies, every line with an amount and a category.
  - Mapping both ways (`EditorDraft(editing:)`, `makeTransaction()`): minor units via
    `CurrencyDigits`, transfer `toAmountMinor`, refund flag, lines with kind/category/position;
    an edit keeps source, import batch, pending flag, booking day and creation time; every
    `PreviewData` transaction round-trips unchanged (test).
  - Delete with confirmation text (R-TX-7; imported ones note that re-importing adds them back),
    Duplicate (new manual transaction with the same values, dated now, new line ids).
  - `TransactionEditorDependencies` (repositories, converter, calendar, now) with `.preview()`;
    `EditorPreviewRules` / `EditorPreviewSettings` in-memory fakes; `TxnLookup` for edit mode.

## Integration notes (for B1 / B3 / wiring)
- Present: `.sheet(item: $editorMode) { TransactionEditor(mode: $0, dependencies: deps) { result
  in editorMode = nil; if result != .cancelled { reload } } }` — `TransactionEditorMode` is
  `Identifiable`. B1: ⌘N / "New transaction" → `.new`; B3: `onOpen(id)` → `.edit(id)`; after
  `.saved`/`.deleted` call `TransactionsViewModel.reload()`.
- Wiring: `TransactionEditorDependencies(transactions: SQLiteTxnRepository, accounts:,
  categories:, events:, rules: SQLiteRuleRepository, settings: SQLiteSettingsRepository,
  converter: <current RateTable>)`. `RateRefresher.ensureRates(for: [day])` for the chosen day
  makes the charged pre-fill available for older dates.

## Interpretations (flag to the owner if wrong)
- A category is required for expense/income (R-TX-3); the picker shows "Choose a category"
  until one is picked or suggested (the prototype always had one selected).
- Event pre-selection applies to new expenses and income (prototype: every non-transfer),
  not only expenses (TA wording).
- Duplicate dates the copy now; the original's event is kept.
- Lines are in the account currency; a line's stored original amount is kept only while its
  amount is unchanged.
