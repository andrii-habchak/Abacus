## Done in this slice (all green)

- **Migration v18** "recurring transactions" in `AbacusStore/Migrations/Schema.swift` (`recurringV18`):
  `scheduledItems`, `scheduledOccurrences`, `forecastSnapshots`, `forecastSnapshotItems`,
  `suggestionDismissals` plus five `idx_…` indexes. CloudKit-safe (STRICT, TEXT primary key, no UNIQUE,
  only CASCADE/SET NULL, `IF NOT EXISTS`). Registered between v17 and v19 (the migrator applies by name).
  Columns follow spec §3 exactly.
- **Entities** `AbacusDomain/Model/Scheduled.swift`: `ScheduledItem`, `ScheduledOccurrence`,
  `ForecastSnapshot`, `ForecastSnapshotItem`, `SuggestionDismissal`, enums `ScheduleUnit`,
  `ScheduleEndKind`, `ScheduleMode`, `ScheduledItemStatus`, `PausedBecause`, `OccurrenceStatus`,
  `OccurrenceMatchKind`. Days are `YYYY-MM-DD` strings; `ScheduledItem.schedule` gives the parsed `Schedule`.
- **`Schedule`** (`AbacusDomain/Calc/Schedule.swift`): occurrence N is computed from the start day only
  (no drift); month-end clamping, "last day of month", yearly 29 Feb, every N units, end by day/count,
  `occurrences(from:through:)`, `next(_:onOrAfter:)` (editor preview), `lastOccurrence`. Calendar-free civil
  arithmetic (`Day.plusDays`, `Day.daysUntil`) so DST/time zones cannot move a day.
- **`ScheduledOccurrences`** (`Calc/ForecastEngine.swift`): `effects(of:)`, `expected(...)` (active items,
  non-archived accounts, unresolved, from today minus grace to a horizon; `isOverdue`), `missed(...)`
  (unresolved past the grace period, to be stored as `missed` at launch). Default grace 14 days.
- **`ForecastEngine.run`** → `Forecast`: balance per day per account (index 0 = today, overdue counts on
  today), `series(for:)`, `netWorth(convert:)` (flat rates, names unconverted currencies), `lowest(for:)`,
  `warnings` (first day below zero for non-liability accounts with the causing occurrences). Pure; 90 days x 30
  accounts x 100 items runs in a few ms.
- **`SubscriptionDetector`** (`Calc/SubscriptionDetector.swift`): R-REC-8 rules (3+ rows, same normalised
  description, amounts within 10 % of median, gaps within +-20 % of median, period near weekly/biweekly/monthly/
  quarterly/yearly, monthly day spread <= 4, newest <= 1.5 periods old, 24-month window, ignores refunds,
  transfers, balance corrections, archived accounts, matched rows, dismissed keys). `normalise`, `key`,
  `dismissalID`. 20 000 rows under 1 s.
- **Tests** (Swift Testing): `AbacusDomainTests/ScheduleTests`, `ForecastEngineTests` (incl. an oracle test
  against `Calc.mainEffects`), `SubscriptionDetectorTests`; `AbacusStoreTests/RecurringV18Tests`.
  Existing `BackupTests` seed and `BackupSnapshotTests` count (v17, v18, v19 pending) were updated for the new tables.
- Gate: `swift test` with `ABACUS_SAMPLES` green; macOS app build see the commit message / report.

## Notes and decisions made while building

- Suggestion keys include type and currency: `"<normalised text>|<type>|<currency>"`; the dismissal row stores
  that key with the account id (`SubscriptionDetector.dismissalID`).
- Detector uses the median (upper median for even counts); a price change above 10 % splits history and hides
  the pattern until three new rows exist (acceptable, spec-conform).
- The monthly day-of-month spread is a plain max-min <= 4 (a pattern around the 30th/1st would be rejected);
  revisit if a real export shows it.
- Forecast `netWorth(convert:)` sums signed balances (a liability account is negative), same result as
  assets minus liabilities in `Calc.netWorth`. Debts held at today's value are not added yet: the UI layer
  must add `DebtBook` terms (R-REC-13) when wiring the net-worth series.
- Overdue occurrences inside the grace period are counted on today in the forecast (Q12).
