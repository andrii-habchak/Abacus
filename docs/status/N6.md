# N6 — Reconciliation (cleared flag, Reconcile, stale holds, balance gaps)

State: done (awaiting merge)   ·   Branch: wp/N6-reconcile   ·   Updated: 2026-11-03

Spec and approved prototype: `docs/status/N6-spec.md` (proposed TA text, `R-CLR-1…9`, owner questions Q1–Q17)
and `docs/design/N6-reconcile.dc.html`. Built in three parts, in this order.

## N6a — cleared flag, migration v19, clearing at import
- `Txn.isCleared` (side on `accountID`) and `isToCleared` (side on `toAccountID`, transfers only);
  `Txn.isCleared(on:)` / `setCleared(_:on:)` (`AbacusDomain/Model/Reconciliation.swift`).
- **Migration v19** (`Schema.swift`, `Migrations/ClearedBackfill.swift`): the two columns (default 0),
  table `reconciliations` (CASCADE only, no UNIQUE), `importTxnSnapshots.kind` (`full` / `flags` /
  `deleted`, default `full`). Backfill by row class: Saldo and PKO rows cleared (transfers per side:
  Saldo both, PKO the side of the batch's account), pending holds not, hand-typed rows linked to a
  bank row (they carry a fingerprint) cleared, balance corrections cleared, the rest not. Runs again
  as a no-op. v18 stays reserved for N5 (names order the migrator, not numbers).
- Import (`CommitBuilder`): rows are created cleared on the file's side (Saldo: every account; PKO:
  the target account); a settled hold becomes cleared; a linked row clears the row account's side and
  gets the booking day; absorbed / completed transfers keep or set the right side. A possible
  duplicate whose existing row is **hand-typed and uncleared** now defaults to **Link** (the bank row
  confirms it); a Saldo or already cleared row keeps Skip.
- Undo: `ImportCommit.flagOriginals` / `deletedTxns` are snapshotted; undo restores only flags, pending
  mark, booking day, amount and day of a linked / settled / edited row (later edits stay) and
  re-inserts a deleted stale hold. `ImportTxnSnapshot.txn()` decodes snapshots written before v19.
- Headless `abacus-import`: same pipeline; stale holds are kept, gaps are listed in the summary lines.
- Reconcile maths and store: `AbacusDomain/Calc/Reconcile.swift` (statement day = `bookedDay` else the
  day; figures; drift; "not reconciled" hint), `SQLiteReconcileRepository` (setCleared, markSettled,
  finish in one transaction).

## N6c — stale pending holds and balance continuity (`AbacusImport/Checks`)
- `StaleHolds`: pending PKO hold on the target account, value day ≥ `staleDays` (5) before the file's
  last booked day, within `coverageDays` (3) of its first, not settled / linked / listed again. Decisions
  Keep / Mark settled / Delete / Edit; all must be made before Import (headless keeps them).
- `BalanceContinuity`: multiset chain check of `Saldo po transakcji` (NormalizedRow now keeps the
  statement amount and balance), gaps with the signed missing amount, file start and end; start check
  against the account's cleared balance (`ImportStore.clearedBalance`). Warnings only; a row next to a
  gap can be removed (skipped).
- History line and Done step carry the counts ("2 stale holds …", "1 balance gap").

## N6b — UI
- Import: Needs review has sub-tabs All / Decisions / Categories / **Pending payments** / **Balance
  gaps** (`ImportChecks.swift`, `ImportChecksViews.swift`); selection by click, ⌘ click, ⇧ click and
  Select all; bulk Keep pending / Mark settled / Delete; "Accounts & categories" is hidden for a PKO
  file without counterparties; the Done step offers "Reconcile <account>" with the file's closing
  balance and day.
- Reconcile (`AbacusFeatures/Reconcile/ReconcileModel.swift`, `App/macOS/Reconcile/ReconcileView.swift`):
  setup step, three figures, To check / Already cleared / After the date, tick, Add transaction, Edit,
  Delete, Mark settled, Add correction and finish, cash (whole balance), drift note. Opened from the
  account window ("Reconcile" next to the balance, with cleared balance, last reconciliation and the
  "Not reconciled" hint) and from the Done step; shown in place of Accounts.
- Transactions: cleared indicator column, **Cleared** filter menu (All / Cleared / Uncleared), real
  multi-selection (⌘/⇧) with Mark Cleared / Uncleared / Settled in the context menu.
- Editor: "Cleared" checkbox(es) when editing, warning when a bank-confirmed row's amount, day or
  account changes; a duplicate starts uncleared; a moved side is uncleared.

## Interpretations (please confirm)
- Typed amounts in Reconcile: a leading "-" is allowed for the closing balance (a card in debt); in
  "Add transaction" no sign or "-" = money out, "+" = money in.
- The "Not reconciled" hint shows in the account window only (not in the account list rows).
- Editing a stale hold also restores its day on undo (the flags restore covers `occurredAt`).
- Selection ⌘/⇧ on the Transactions list comes from switching the list to native multi-selection.

## Not done / not checked
- Not checked visually in the running app: the Reconcile screen, the two new Needs review sub-tabs, the
  cleared column and filter menu, the account window card, the editor checkboxes.
- Reconcile has no ⌘/⇧ row selection (checkboxes and Tick all only).
- The "Not reconciled" badge is not in the Accounts list rows.
- Deleting a stale hold does not restore its fingerprint on undo (the hold comes back, its old
  `hold|…` key does not).
