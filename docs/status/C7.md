## Interpretations (for the orchestrator to confirm or move to DECISIONS)
1. **Editor suggestion**: transfer rules never suggest in the editor (it would switch the type
   on its own); the editor uses the first matching *category* rule. Transfer rules apply on
   import and on "Update existing transactions".
2. **Apply to existing = confirmation + Undo**: Save & apply first shows "Update N transactions?"
   with what happens; after it, a banner offers Undo (restores the transactions and the rule —
   a new rule is deleted) until the next change on the screen. The rule is applied on its own,
   whatever its position; a category rule overwrites another category.
3. **Never changed**: transfers (both actions, so halves of paired transfers stay), income by
   an expense-category rule and vice versa.
4. **Transfer amount in another currency**: same currency → same amount; otherwise the original
   amount when it is in the other account's currency; otherwise the rule does not apply (import:
   the next rule is tried). Money in with attached records is skipped (the records would move
   to the other account). A transfer rule skips a row whose account is the rule's account.
5. **Precedence on import**: file category / user pick > rules (unchanged); amount comparisons
   are strict; a per-account rule never matches an account the import creates.
6. Rule amounts are stored in minor units of 1/100 (every currency has 100 minor units, D-Money).
