# C29 — Accounts: kind change, kind filter, archive with balance, settle prompt

Owner-approved requirements (R-ACC-1…5, R-MGMT-9, R-DEBT-17/18/21, v1.9 wins). Lane C28 works on the
Transactions list in parallel; this lane keeps out of `Transactions/` except the one-line exclusion
described under "Outside the owned paths".

## Design

### 1. Kind change (R-ACC-1, R-ACC-2, R-DEBT-17, R-DEBT-18)
- Any account may change to any kind, with transactions or not, to or from "Debt (person)".
  `ManageText.liabilityKinds(offeredFor:)` is replaced by `liabilityKinds(debtsAvailable:)`: the
  Debt kind is offered whenever the app has a debt repository (the editor can then link it).
- A kind "Debt (person)" needs a debt: with the debt section available, Save is blocked with
  "Choose or create the debt for a Debt (person) account." until the Debt field is not None.
- **The link role stays as it is.** An account already linked keeps its role (external stays
  external) on a kind change; the old "role follows the kind on Save" rule of C26 is dropped for
  existing links. A *new* link takes its role from the account's **stored** kind before the save
  (a new account: the chosen kind): Revolut Anna (a Bank account with a statement) that becomes
  "Debt (person)" and gets linked is therefore **external**, which is what it is.
- Note in the sheet when the class changes (asset to liability or back): the balance is listed under
  Liabilities instead of Assets in net worth (the total does not change: assets − liabilities counts
  the signed balance either way); an account linked to a debt is counted only through the debt
  (R-DEBT-18) and the note says so.

### 2. Kind filter (R-MGMT-9)
- `AccountsModel.kindFilter: Set<AccountKind>`, `kindOptions` (kinds that exist among the accounts
  under the current currency filter, plus any kind already selected so it can be removed),
  "Clear filters" resets currency + kinds (+ nothing else). The currency options cascade the same
  way (currencies that exist under the kind filter). Search, archived toggle and sort are not filters.

### 3. Archive with a non-zero balance (R-ACC-4)
- Zero balance: the old one-line confirmation. Non-zero: `AccountArchiveSheet` (balance, Cancel,
  Archive, checkbox "Create a compensation transaction").
- Compensation = one transaction on the account: income when the balance is negative, expense when
  positive, amount = |balance| in the account currency, today, category "Balance correction"
  (the existing one of that kind, else created), note "Zeroes the account on archiving.",
  `isBalanceCorrection = true`.
- **Exclusion from reports without touching other transactions:** new column `txns.isBalanceCorrection`
  (migration v14, append-only, `INTEGER NOT NULL ON CONFLICT REPLACE DEFAULT 0`, no constraint/index,
  CloudKit-safe). `Calc.reportEntries` (the single source of the donuts, budget, events, list totals and
  "income vs expenses") returns nothing for a flagged transaction; the SQL spending query and the list
  totals helper skip it too. The transaction stays in the account list and in every balance and the
  net-worth series (those do not look at the flag).
- Debt-linked account: no compensation checkbox. Checkbox "Forgive the debt (amount CUR)" creates a
  manual record in the account's currency, dated today: balance > 0 (they owe me) = `forgaveThem` with
  "Count as expense" (R-DEBT-4, default on); balance < 0 = `forgivenByThem` (no flag offered).
  The archived account stays linked and keeps counting in the debt balance, so the debt's balance in
  that currency becomes 0 after the record when this was its only account in that currency.
  Unchecked: archive without touching the debt.

### 4. Settling a debt (R-DEBT-5, R-DEBT-17, R-DEBT-21)
- Mark settled (Debts tab header, row and widget menus) with non-archived linked accounts asks
  "Archive the related accounts?": a checkbox per account, virtual ticked, external not; Cancel / Settle.
  Chosen accounts are archived **as is, without compensation** (the debt is already settled). Without
  such accounts the debt is settled directly. Reopening does not unarchive anything.
