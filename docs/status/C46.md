# C46 — Rule suggestion on every Needs review card
State: done (awaiting merge)   ·   Branch: wp/C46-rule-suggestion-ui   ·   Updated: 2026-11-01

Owner report (S2): no rule information on Needs review cards, e.g. "Transfer to an own account in another
currency" resolved as "Transfer to my account" with an estimated other side; check also "Unknown operation
type" with Expense + a category, and a pre-filled "suggested" choice.

## Root cause
- C42 built the proposal only for reason **Unknown operation type** (`reviewRule` in `ImportPreview.swift`
  guarded `case .unknownOperationType = review.reason`). Cards of reason *Transfer to an own account in another
  currency* (`transferAmountUnknown`) and *unpaired transfer half* never got `learnedAction`, so the card had no
  line, the bulk sheet listed nothing and no rule was saved. This is the owner's first case.
- It also required `row.createsTransaction`; a transfer whose other side is a found transaction (C38 absorb)
  has `createsTransaction == false`, so even that resolution of an unknown type gave no rule.
- The card line was drawn only when a rule would be saved (gray, one line, not the category row's style). When
  an enabled rule already matched the text, or the choice was Expense without a category, the card showed
  nothing at all, with no hint why. That is the likely explanation of the owner's "Unknown operation type /
  Taxes › ZUS" observation (an existing matching rule, or no category yet); with a synthetic ZUS row and a
  category the line does appear (test + screenshot below). The real database was not inspected.

## Fix
`AbacusImport`:
- `reviewRule` now works for **all** reasons: Expense/Income of the sign's kind with a category → category rule,
  Transfer to my account → transfer rule, Debt… → debt rule. Not expressible (nothing proposed): Skip, Pair with…,
  a record without category, a record of the other kind (reversal). The row must import (created, or taking
  over a found transaction).
- When an enabled rule already matches, nothing is proposed and `ReviewInfo.matchingRule` carries its label.
- **Next import:** for review reasons a rule cannot resolve on its own (amount unknown, unpaired half), a matching
  rule now makes the card's **suggestion** (`ReviewInfo.suggested`, `suggestedByRule`, `suggestingRuleLabel`):
  its category (`record`), its account (`transfer`, not for unpaired halves, which offer no transfer) or its debt.
  The card still waits (the other side or the missing half needs the user); "Use suggestions" applies it, except
  a transfer whose amount on the other account is unknown, which stays open (no error). Unknown types are still
  resolved outright by a matching rule (C36/C42).

`AbacusFeatures` / app:
- `ImportReviewItem.ruleNote` is an `ImportNote`; the card draws it with `ImportNoteText` + the same link button
  as a category row (blue "Will be saved as a rule “…” → …" + "Don't save"; "Not saved as a rule" + "Save as
  rule"). Other lines: "Suggested by rule “…”" (green, undecided card), "By rule “…”" (the rule's suggestion
  confirmed), "Rule “…” already matches this text; no new rule", "Choose a category to save it as a rule"
  (Expense/Income without a category). Skip and pairing show nothing.
- A rule's suggestion pre-fills the card's category / account, so confirming it keeps them; a
  *Transfer to an own account in another currency* card pre-fills the account found by its number (before, the
  first account A–Z, e.g. "Monobank Black", was taken when clicking Transfer to my account).
- Bulk Category / Account / Debt already open the Save rules sheet from `learnedAction`; they now list the
  rules of every reason (test: a transfer card and an unknown-type card in one bulk Category).
- DEBUG launch options for UI checks (with `-AbacusImportFile`): `-AbacusImportAccount <name>` picks the
  statement account, `-AbacusImportResolveReview YES` resolves the cards as a user would.

## Interpretations / caveats
- A rule learned from an amount-unknown transfer uses the payee text (often the owner's own name); it would also
  turn other rows with that text into transfers to that account when their amount in its currency is known.
  The line is on by default as the owner asked; "Don't save" turns it off.
- Rules saved from these reasons do not resolve the next card silently; they mark the suggestion.
