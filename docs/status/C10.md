# C10 Categories — status

_Branch `wp/C10-categories`. TA v1.6 R-MGMT-8, R-MGMT-7, R-MGMT-10, R-MGMT-11, R-CAT-*; D47._

## Done

- **Same colour everywhere (bug).** Root cause: the dashboard donut drew every slice except
  the picked one at 60 % opacity, and the pick (`DashboardModel.selectedSlice`) stays set after
  a drill-down. Back on the dashboard all other slices were lighter than the legend dots and
  the Categories page, and the close palette hues (olive / green / teal) looked the same.
  Besides that there were three hex→colour functions (`DashboardStyle.color(hex:)`,
  `ManagePalette.hex`, `TxnPalette.tile`) with different parsing and fallbacks (6 digits only vs
  any length; with or without `#`; three different greys). Now: one `CategoryColor`
  (`App/macOS/Shell/CategoryColor.swift`, parsing = `ColorPalette.rgb`, sRGB) used by all of
  them, no dimming (the picked/hovered slice still pops out by radius), donut slices carry the
  normalised category colour (a child without one takes its parent's). Test
  `CategoriesPageTests.donutColours` checks every slice and child against the category colour.
- **Built-in Uncategorised (D47).** `AbacusDomain/Model/Uncategorised.swift`: title
  "Uncategorised" (one spelling: list rows and attached lines, donut slice, filter menu, event
  bars, drill-down comments), default colour amber `#C99A00`, setting
  `SettingKey.uncategorisedColor`. Not a DB row: the Categories page pins it on top of both
  tabs (pin icon, "Built in" badge, count of expenses/incomes without a category, not
  draggable, no drop target); its inspector edits the colour only (name read-only, no parent,
  no archive/delete). Saving reports `onDataChange`, so the list and dashboard re-read.
  `TransactionsViewModel` takes an optional `settings:` (live session passes SQLite) and
  `TransactionsReference.uncategorisedColor`; rows without a category get that colour.
  Imported categories named "Uncategorised …" stay ordinary categories.
- **A–Z pickers.** Shared helper `AbacusFeatures/Manage/CategoryOrder.swift`:
  `CategoryOrder.alphabetical(_:)` (parents A–Z, each followed by its children A–Z,
  `localizedStandardCompare`), `CategoryOrder.byName`, `CategoryOrder.tree(_:by:)` and
  `CategorySort`. Used by the editor (`EditorReference.categoryOptions`, lines too), the
  transactions category filter (`TransactionCategoryTree.options`, expense then income), import
  review pickers and Saldo category mapping options, the Categories inspector's Parent picker
  and the delete dialog's target picker. **Budget (C8) and Rules (C9) lanes: use
  `CategoryOrder.alphabetical(categories.filter { … })` for your pickers.** Events have no
  category picker (event bars are by amount).
- **Sort selector** on the Categories page: Name A–Z, Name Z–A, Custom order, Newest first,
  Oldest first; remembered in `SettingKey.categorySort` (default Custom order).
- **Migration "v9: category createdAt"** (registered last, after v6 on this branch): adds
  `categories.createdAt TEXT NOT NULL ON CONFLICT REPLACE DEFAULT '2000-01-01 00:00:00.000'`
  (only if missing), then numbers existing rows one second apart from 2000-01-01 in the order
  (kind, position, name, id), so "Oldest first" starts as the custom order and every category
  created later is newer. `Category.createdAt` (init default now, truncated to whole seconds so
  it reads back equal). CloudKit-safe (no constraint beyond the default; backup copies columns
  dynamically). Name "v9" leaves v7/v8 to the parallel lanes; the orchestrator keeps it last.
- **Search**: full-width `PageSearchField` at the top; matches category and subcategory names;
  a matching subcategory shows its parent above it (dimmed when the parent itself does not
  match); "No categories match …" when nothing does.
- **Drag and drop like Reminders** (`CategoriesModel.drop(_:on:position:)`, `canDrop`): the top
  or bottom ~28 % of a row = between rows (reorder; the sort switches to Custom order and the
  order the user saw becomes the custom order), the middle = onto the row (becomes its
  subcategory, last in the group; onto a subcategory = sibling of it; sort unchanged). Rules:
  one level (a category with subcategories can't be nested; onto falls back to a reorder),
  same kind (tabs), between top-level rows a child becomes top level, right below a parent
  whose subcategories follow it becomes the first subcategory, the space below the list =
  top level, last. Indicator: accent line above/below or an outlined row. The repository's
  existing save rules (one level, same kind) still guard every write; transactions and budget
  limits keep their category id (budget calc already handles parent/child limits).
- **Only "New category"** in the toolbar ("New subcategory" removed; a subcategory comes from
  drag and drop or the inspector's Parent field, kept).
- **New transaction preselects the category**: `TransactionEditorMode.newInCategory(id)`,
  `AppModel.newTransactionCategory` hook (set by `AppSession`: the selected, non-archived
  category while the section is Categories). The editor applies the usual defaults, then the
  category and the matching type (income/expense).
- **Save bottom-right** in the category inspector (`CategorySaveFooter`, Revert/Cancel to its
  left, ⌘S), pinned to the bottom of the inspector. The shared `ManageSaveBar` is untouched.
